# PRD fork#760 — Restore a human-typed workspace slug, decoupled from the orchestration Name; periodic sync for persistent workspaces

**Issue:** [prageethw/dot-agent-deck#760](https://github.com/prageethw/dot-agent-deck/issues/760)
**Priority:** Medium
**Status:** Both parts implemented. Part A (restore the "Worktree slug" field) implemented on PR [#761](https://github.com/prageethw/dot-agent-deck/pull/761), then **reverted** (2026-09-13/14) via PR [#771](https://github.com/prageethw/dot-agent-deck/pull/771) per the maintainer's direct decision — see the amended Decisions table below. Workspace identity is once again `(source folder, Name)` directly, matching PRD fork#544's original design; the friction PR #761 was meant to fix (a long descriptive Name becoming the workspace's folder/branch name almost verbatim) is accepted as the tradeoff for that simplicity. **Predecessors:** PRD [fork#544](https://github.com/prageethw/dot-agent-deck/issues/544) ("named, persistent orchestrator workspaces") retired the pre-existing separate "Worktree slug" field and made the workspace directory/branch derive solely from the orchestration Name. PRD [fork#192](https://github.com/prageethw/dot-agent-deck/issues/192) ("orchestration names as instance identity") is unaffected — Name keeps its job as the tab title and the `ClaimOrchestrationName` uniqueness key.

**Fork-only?** No — the underlying code (`src/ui.rs`'s New Pane form and spawn path) is upstream code, same as fork#544/fork#325. Offer upstream per rule 19 once shipped, since fork#544 (the PRD this partially reverts) was itself upstream-eligible code.

## Problem Statement

PRD fork#544 kept a genuine improvement — persistent, resumable isolated-clone workspaces instead of `orchestrator-N` auto-numbered sprawl — but, in doing so, collapsed two previously-independent identities (the descriptive orchestration Name, and a short slug naming the on-disk workspace) into one. Since #544, a long, descriptive Name becomes the workspace's folder and branch name almost verbatim, because Name is the *sole* input to `sanitize_workspace_segment`/`resolve_workspace_path` (`src/ui.rs`) — e.g. Name `"implement 8 features baseline intent"`, picked at a git toplevel named `im`, becomes the directory `im-implement-8-features-baseline-intent` (spaces sanitized to dashes).

**Correction (2026-09-14):** an earlier draft used the example `im-8-features-baseline-intent` here, conflating this with a different, unrelated mechanism. For a NESTED pick specifically (a subdirectory inside a git repo, not the repo's own top level), `disambiguate_workspace_segment` (fork #607) joins the segment with the picked subdirectory's own relative path as `{segment.len()}-{segment}-{sanitized_subpath}` — a repo `im` with typed segment `features` (8 characters) picked at subdirectory `baseline/intent` produces `im-8-features-baseline-intent`, where `8` is `len("features")`, a disambiguation length-prefix that is never part of anything typed, appearing only for a nested pick.

Discussed with the maintainer (2026-09-12): the fix is not to revert fork#544's persistence/reuse model, but to decouple naming ergonomics from it again — restore a short, human-typed, stable identifier independent of the descriptive Name, matching the pre-#544 design, while keeping every collision-safety/disambiguation fix layered on top since (#607, #595, #751).

A second, related gap surfaced in the same conversation: a persistent, long-lived, reused workspace has no periodic freshness mechanism. `worker-agent-deck worktree sync` (fork #744) only runs on-demand, as one step the orchestrator triggers right after a merge. Nothing keeps a workspace that stays open and reused over days/weeks current with `origin/<default branch>` between merges.

## Decisions

| Question | Direction | Why |
|---|---|---|
| Does Name go back to driving the workspace path? | **No.** Name stays exactly what fork#544 and fork#192 made it: the tab title and the `ClaimOrchestrationName` uniqueness key. It never feeds `sanitize_workspace_segment`. | Restoring Name-driven paths would just reproduce the original PRD fork#544 problem (auto-numbered sprawl) that #544 fixed. The regression being fixed here is narrower: the *replacement* input (a typed slug) that #544 removed. |
| What drives the path instead? | A restored, optional `FormField::WorktreeSlug` field. Non-blank slug (validated: non-empty after trim, first char alphanumeric/`_`, remaining chars alphanumeric/`-`/`_`) is used verbatim as the segment. Blank slug auto-generates `orchestrator-N` (`auto_generate_worktree_slug`, exactly the pre-#544 fallback) — **not** derived from Name. | Matches the actual pre-#544 behavior byte-for-byte (verified against `git show 275904eb^:src/ui.rs`), rather than inventing a new fallback (an earlier draft of this fix incorrectly proposed falling back to Name-derived text; corrected before merge). |
| Does the existing collision-safety machinery need to change? | No. `disambiguate_workspace_segment` (fork #607's length-prefixed join), the symlink-toplevel guard (fork #595), and resume-vs-create matching (`provision_isolated_clone_sync_resolved`'s directory-exists check) all operate on the opaque `segment` string produced above — they are unchanged, just fed a different (slug-or-auto-generated) input. | These fixes were hard-won across multiple review rounds; the goal is decoupling the *input*, not re-deriving the safety logic. |
| Should persistent workspaces sync periodically, or only post-merge? | **Decided 2026-09-14 — see the second amendment below.** Superseded the original "daemon timer or TUI-triggered fetch" candidate list with a cheaper, prompt-level mechanism: embed the safe-main-sync step into the orchestrator's own startup instructions. Still must preserve `worktree sync`'s existing safety property (only fast-forward/switch when the workspace carries nothing extra — never discard uncommitted or unmerged local work). | Original text kept for history; see the amendment for the actual decision and its accepted tradeoff. |

### Amendment (2026-09-13/14): Part A reverted

After PR #761 shipped (and after fix rounds for its own friction — #763, #766 — landed on top of it), the maintainer revisited the decision directly and reversed it:

| Question | Direction | Why |
|---|---|---|
| Does the `FormField::WorktreeSlug` field stay? | **No — removed entirely.** `resolve_workspace_path`'s segment input reverts to `sanitize_workspace_segment(Name)`, exactly PRD fork#544's shape. `auto_generate_worktree_slug` and `is_valid_worktree_slug` are dead code, removed. | Maintainer's own words: "we used to just use name given to uniquely identify tab along the folder user selects." The two-field model (Name for display, slug for the path) was judged not worth its own ongoing friction — #763 (nested-pick short-name handling) and #766 (legacy-marker-format resume) were both bugs in the slug field's own machinery, not in the underlying persistence/reuse model. |
| Does PRD fork#544's persistence/reuse model survive the revert? | **Yes, unchanged.** Persistent, resumable isolated-clone workspaces (instead of `orchestrator-N` sprawl) were always the real improvement this PRD's Problem Statement credited to fork#544; only the *naming input* is reverting, not the reuse mechanism. | This was fork#544's actual contribution and was never in question, in either direction of this PRD. |
| Does the collision-safety machinery added since #544 survive? | **Mostly yes, since most of it is segment-source-agnostic:** `disambiguate_workspace_segment` (fork #607), the symlink-toplevel guard (fork #595), and the resolved-workspace-path-qualified `creator` identity (this PRD's own third fix round, closing a cross-repo collision) all operate on whatever string feeds them and don't care whether that string came from a slug or from Name — they stay, now fed Name's sanitized output. The daemon-side `cwd`-as-exclusive-resource-key guard this PRD's fourth fix round added to `ClaimOrchestrationName` also stays, for the same reason: two different Names whose sanitized segments happen to collide are exactly as reachable as two different Names sharing a typed slug were. | These are genuine, still-relevant safety improvements independent of which field feeds the segment — reverting the field they were built for doesn't make the problem they solve go away. |
| What does NOT survive? | The slug-field-specific bug fixes layered on top by #763/#766/#769: the nested-pick short-name handling for a *typed* slug (`spawn_pane_creator_identity_seed`'s digest-fronted seed, unreachable once no caller can ever diverge `physical_worktree_path` from the always-folded `workspace_resolution.worktree_path`), the `scan_by_shape` structural workaround in `live_orchestration_occupies` (existed only because the slug field broke the "segment always equals `sanitize_workspace_segment(Name)`" assumption `scan_by_name` relies on), and the tests/CATALOG.md entries pinning slug-specific behavior. The legacy-marker-format migration logic in `issue_dispatch_run.rs` (bridging a pre-third-fix-round Name-derived marker to today's path-derived one) stays — it is not slug-specific, and a real on-disk workspace from #760-era local testing may still need it to resume. | Once segment is unconditionally Name-derived again, code that exists solely to handle a typed-slug-vs-folded-path divergence has no live caller left; keeping it would be dead complexity with no test coverage worth the name. |

### Amendment (2026-09-14): Part B decided — embed into the orchestrator startup prompt

The original candidate list (a daemon timer across all live isolated-clone workspaces, or a TUI-triggered fetch on tab focus) is superseded by a cheaper, prompt-level mechanism:

| Question | Direction | Why |
|---|---|---|
| Where does the sync happen? | **Framework code, not a project's own `.dot-agent-deck.toml`.** `src/orchestrator_context.rs`'s `build_orchestrator_context` already assembles every orchestrator's startup context from three pieces: (1) the project's own `prompt_template`, (2) a framework-generated "Available agents" list, (3) a framework-generated, hardcoded "## Delegation protocol" section that applies unconditionally regardless of what a project's `.dot-agent-deck.toml` says. The safe-main-sync instructions belong as a FOURTH such framework-generated section, alongside "Delegation protocol" — hardcoded in this function, not hand-written into any project's own config. Whenever an orchestrator starts or resumes against a mapped folder, this section must instruct it to: (1) inspect the mapped repository state (dirty files, staged changes, untracked files, local commits, branch divergence), (2) fetch latest `main`, (3) safely sync/integrate `main` via the repository's documented safe merge/rebase workflow, (4) preserve all existing local/uncommitted/unmerged work — never a hard reset/clean, (5) surface unresolved conflicts and stop normal work until the workspace is verified safe, (6) only then continue with normal orchestration. | Correction from this amendment's first draft, which wrongly proposed hand-writing this into THIS repo's own `.dot-agent-deck.toml` `prompt_template` — that would only ever help orchestrators working on `dot-agent-deck` itself; every other project using the tool would need to separately copy the same text into their own config to get the same safety behavior. A framework-level change in `build_orchestrator_context` applies to every project unconditionally, the same way the Delegation protocol section already does, with no per-project opt-in needed. |
| Does this replace the daemon-timer/TUI-triggered candidates entirely? | Accepted as the first, cheap step for the common case — not as a durable guarantee. **Known tradeoff, recorded rather than silently accepted:** a prompt-level instruction inherits CLAUDE.md rule 17's documented decay problem — role prompts are delivered once at spawn while a long session's context can age past it, especially across a compaction. If that turns out to matter in practice, the original daemon-timer/TUI-triggered candidates remain the fallback, as a code-level guarantee that can't be "forgotten." | Ship the cheap fix now; don't let the search for a perfect durable mechanism block the common case from getting fixed at all. |
| Does this need the experimental-flag question (CLAUDE.md rule 9)? | No — this isn't a new user-visible TUI surface, it's a change to the orchestrator's own startup instructions/behavior. Rule 9 is scoped to a PRD "introducing a new user-visible surface." | Rule 9's own trigger condition doesn't apply here. |
| Regression coverage? | Add a unit test on `build_orchestrator_context`'s output confirming the safe-main-sync section appears exactly once, following the existing pattern of tests in `src/orchestrator_context.rs` for the Delegation protocol section (guards against duplicate injection if startup instructions are also injected elsewhere via a different seam, and against the section silently disappearing as the function evolves). | Matches this file's existing test convention rather than inventing a new one. |

## Out of Scope

- Auto-deletion/reclaim policy (`worktree reclaim`, pin/unpin) — unaffected, per the maintainer's explicit direction. Issue #546 is already resolved and needs no further change here.
- Any change to Name's role as instance identity (PRD fork#192).

## Milestones

- **Part A (done, PR #761; reverted branch `feat/760-name-driven-workspace-identity`):** Restore `FormField::WorktreeSlug`, wire it into the segment-derivation call chain, restore `auto_generate_worktree_slug` for the blank case, update stale doc comments asserting "Name is the sole input," add/update tests (`orchestration/worktree/017`-`020` plus updated fixtures in pre-existing `orchestration/workspace`/`orchestration/worktree` tests). **Reverted 2026-09-13/14** per the amended Decisions table above: the field is removed, segment reverts to `sanitize_workspace_segment(Name)`, and the slug-field-specific test/doc machinery (including #763/#766's own fix-round tests) is removed with it.
- **Part B (decided 2026-09-14, implemented and merged 2026-09-14, PR [#775](https://github.com/prageethw/dot-agent-deck/pull/775), squash commit `69024f05` on `main`):** Embedded the safe-main-sync sequence into `src/orchestrator_context.rs`'s `build_orchestrator_context` — a new framework-generated "## Workspace sync" section alongside "Delegation protocol", per the second amendment above. Not project-level `.dot-agent-deck.toml` text. Runs on both new and resumed sessions (fresh spawn via `prepare_orchestrator_prompt`, compaction/`/clear` reassertion via `reassert_orchestrator_prompt`), with regression coverage confirming the section appears exactly once and precedes the other framework-generated sections. Preserves `worktree sync`'s uncommitted/unmerged-work safety guarantee throughout: a dirty workspace skips the sync and reports rather than fetching/merging over it, and a merge conflict stops with `git merge --abort` rather than force-resolving. Went through three rounds of delegated `reviewer`/`auditor` passes (CLAUDE.md rule 8) before merge — round 1 found the dirty-check didn't gate the merge and the startup pointer never mentioned the sync step; round 2 found the round-1 fix over-corrected into halting orchestration indefinitely on a merely-dirty tree; round 3 approved with no blocker.
