## `daemon status --json` reports each pane's delegation-watch state

The `daemon status --json` document now carries three additional optional fields per agent, joined from the daemon's own delegation bookkeeping: `outstanding_delegation` and `silence_watch` (the idle-worker and silent-worker watches, each `{ armed_secs_ago, orchestrator_pane_id }`), and `delegation_commission` (issue #448's commission ledger — how many delegations to this pane still owe a `work-done`, as `{ outstanding, oldest_armed_secs_ago, orchestrator_pane_id }`). All three are omitted when not armed, so existing consumers parsing tolerantly are unaffected.

The commission ledger's own age-based expiry (for `vfarcic/dot-agent-deck#590`) is a fixed, config-independent window rather than derived from `worker_response_timeout_minutes` or `delegate_no_event_window` — upstream #590's explicit ask, since coupling the ledger to a switchable detector let disabling that detector make a delegation indistinguishable from one nobody made. Each still-unanswered delegation to a worker pane is now aged independently rather than sharing one pinned timestamp, so one long-outstanding delegation can no longer cause a much fresher sibling's genuine completion to be misreported as unsolicited and have its summary silently dropped.

## M4: `delegate --subject` / `work-done --subject`, and a mismatch warning in the orchestrator's pane

Both `delegate` and `work-done` gain an optional `--subject "#<n>"` flag — a short tag (an issue/PR number, or another short opaque token) naming what a delegation is for. When an orchestrator tags a delegation and the worker's own `work-done --subject` disagrees, the daemon prepends a `⚠️ SUBJECT MISMATCH` warning to the feedback it types into the orchestrator's live pane, naming both the delegated and the echoed subject, so the orchestrator can verify the report's actual content before trusting it. The warning only ever augments the normal `Filed` notification — it never replaces or suppresses the pointer to the worker's report. Both flags are opt-in: a delegation or completion that supplies neither subject is compared to nothing and never triggers the warning.

The delegated and echoed subject values are worker-supplied and worker-echoed free text reaching a live, tool-capable orchestrator's input on the ordinary delivery path, so both are sanitized before they can appear in the warning — whitespace-collapsed, stripped of the same control/ESC/bidi and frame-alphabet characters `quote_untrusted_role` already strips from a role name, and capped at 200 characters — the same defense-in-depth already applied to the report body this warning sits beside.
