## Orchestration name uniqueness is now scoped per directory

Opening a new orchestration whose name is already in use no longer refuses the open outright. The uniqueness check — both the client's suggested `<name>-orchestrator-N` and the daemon's authoritative claim — is now scoped to the orchestration's own resolved working directory rather than to the name alone: two orchestrations with the same name in two genuinely different directories can now both open, while a same-name, same-directory collision is still refused exactly as before.

A claim from a peer old enough to predate this change (`cwd` absent on the wire) is treated as a global wildcard, matching the old name-only behaviour for that peer and never allowing a real collision through.
