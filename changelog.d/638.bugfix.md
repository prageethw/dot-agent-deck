Fixes an interactive `codex` pane getting stuck showing "Thinking" forever, and a related false "Idle" reading mid-turn. Guessing turn state from the interactive TUI's raw redraw text turned out to be unreliable in both directions — a repaint batch carrying only the composer's idle placeholder (with no co-resident spinner text) could still read `Idle` mid-turn, and a turn's closing footer could carry no marker at all and leave the card wedged at `Working` once the session went quiet. For a session where Codex's own native hooks are confirmed installed and trusted (the common/default case), the wrapper now defers to those hooks — the same `UserPromptSubmit`/`Stop` signals that already drive every other agent's card — instead of guessing from redraw text, so the wrapper only reports a text-derived status change on a real turn boundary: specifically, only the JSON `type`-discriminator branch of the classifier still runs for such a session, kept alive because Codex's own `Stop` hook never fires for a turn that ends in a server-side error (confirmed via live measurement against real Codex builds), so that case still resolves to `Error` instead of leaving the card wedged at `Thinking`; the plain-text substring heuristic itself no longer runs at all for a hook-trusted session. Text-based classification (both branches) remains as a best-effort fallback for the narrower case where hook trust could not be confirmed, with the same residual mid-turn/end-of-turn flicker described above — a known and accepted limitation of the no-hooks path (tracked in #640).
