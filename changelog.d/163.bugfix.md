Fixed a rare deck-wide shutdown hazard where signalling one agent's descendants could hit an unrelated process instead. During shutdown, worker-agent-deck waits briefly for each agent to exit on its own before force-killing whatever is left; checking whether an agent had already exited could, in rare cases, release its process id back to the operating system before the force-kill ran, and the OS could hand that same id to a completely different process in the meantime — which the deck would then signal by mistake.

The deck now checks whether an agent has exited without releasing its process id until the force-kill step actually runs, closing that window. This also restores full coverage of the case the check exists to protect: an agent descendant that outlives its own leader process (for example an MCP server or a background tool the agent started) is still force-killed during shutdown even when the leader itself already exited, on every platform the deck supports.
