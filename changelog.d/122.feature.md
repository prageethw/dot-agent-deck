**New: an orchestration tab can root itself in its own git worktree instead of the deck's shared directory.** Type a slug in the new-pane form's Worktree field (shown once you've picked an orchestration) and every role pane spawns inside a sibling worktree named `<repo>-<slug>` — created from the picked directory on tab open, on the branch named after your slug — instead of sharing the deck's own checkout. Leave the field blank and nothing changes: panes spawn in the deck's directory exactly as before.

**This closes the multi-orchestration collision the deck has warned about since PRD #140.** Two orchestrations working the same shared checkout can step on each other's uncommitted files; a dedicated worktree per orchestration makes that class of mistake impossible instead of merely flagging it.

**If the worktree can't be created — the directory isn't a git repository, or a worktree already claims that path — the tab never opens.** The failure is surfaced in the status bar and nothing is spawned: no tab, no role panes, no partial state to clean up.

**Be aware of the scope: the worktree is created when the tab opens and is never removed automatically, including when the tab is closed.** Auto-removal risks destroying uncommitted work sitting in it, so cleanup is left to you for now — the same discipline the rest of the deck asks of a manually-created worktree.
