## Attach-protocol bump: kept-worktree signal (`PROTOCOL_VERSION` 7 → 8), and issue-dispatch no longer force-removes a dirty worktree on close

**Wire-shape change.** Closing a dispatched tab/card can now leave its worktree on disk instead of removing it — uncommitted work, a status probe that itself failed, or the removal itself failing — and the daemon needs a way to tell an attached TUI where the work survives. The daemon→TUI event broadcast (`BroadcastMsg`, forwarded over the attach socket's `KIND_EVENT` frame) gained a new `worktree_kept` variant carrying the retained path and why. That is a wire-shape change an older peer would fail to deserialize, so `PROTOCOL_VERSION` bumped from 7 to 8 and the attach handshake refuses across the mismatch — the same reason PRD #120's own `orchestration_surface` variant bumped 3 → 4.

Compatibility impact: a TUI and daemon must be on the same `PROTOCOL_VERSION` to interoperate. The daemon deliberately outlives the TUI, so after upgrading in place an older still-running daemon and the new TUI will fail the handshake until the daemon is restarted (the standard recovery the build-version handshake already prompts for). Hook events, the single-agent live-surface path, and `orchestration_surface` are unchanged.

**Behavioural change.** Scheduled issue-dispatch (issue #120) used to `git worktree remove --force` a dispatched worktree on tab close, unconditionally discarding any uncommitted work the agent had left behind — the removal policy the shipped code cited for this was that a surviving worktree reads as "issue already claimed" to `dispatch_decision` and would skip that issue on every later fire, forever. This PRD unifies issue-dispatch onto the same `KeepIfDirty` policy the (unscheduled) `dispatch` CLI subcommand already used: a **clean** worktree is still removed and its slot freed immediately, but a **dirty** worktree — or one whose status couldn't be checked, or one `git worktree remove` itself failed against — is left in place instead of discarding the work, and every attached TUI is notified where it's sitting. `dispatch_decision` still sees the surviving path and still (correctly) skips the issue on later fires, so the slot is **not** freed until you resolve the worktree's contents and run `worktree reclaim` yourself — `worktree list --json` reports a kept, deck-marked `#120` worktree as `owned: true`, and once its dirtiness is resolved and its PR merges, a bare `worktree reclaim` frees the slot.

If you were relying on issue-dispatch silently discarding a dirty worktree to keep the slot cycling automatically, that no longer happens — you (or `worktree reclaim`, once the tree is clean and its PR has merged) now have to clear it explicitly.

Prose in this fork calls the product `worker-agent-deck`; the binary name in a command you would actually paste and run is still `dot-agent-deck`.
