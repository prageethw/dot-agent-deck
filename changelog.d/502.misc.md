`drift-check.yml` now files a GitHub issue (labeled `drift-check-alert`) when the drift measurement goes red, and closes it automatically once the check recovers — as a separate `notify` job that runs regardless of the `drift-check` job's outcome, so `drift-check`'s own pass/fail conclusion stays accurate. Previously a red run was only visible on the Actions tab, and drift went unnoticed for days at a time (fork issue #502).
