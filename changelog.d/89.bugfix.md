Bounded a pane's first-prompt lookup so it can no longer hang forever. `dot-agent-deck get-seed` — the call an agent's extension (e.g. the bundled Pi extension) makes to pull its seed prompt natively at session start — asks the daemon for that prompt over the hook socket and previously had no read or write timeout of its own, relying entirely on the daemon closing the connection to know when to give up. A daemon that accepted the connection and then went silent without replying or closing it would leave `get-seed` waiting indefinitely.

The request is now bounded at 5 seconds, and a timeout folds into the same "no seed" outcome as a daemon that closes without answering, so the pane falls back to the PTY-injection safety net instead of hanging. This is defence-in-depth rather than a fix for something observed: no user has hit the hang, since the daemon's line reader reacts promptly to EOF today. The change removes a latent failure mode, not an active one.
