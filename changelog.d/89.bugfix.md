A daemon that goes silent no longer hangs a pane's first-prompt lookup. `dot-agent-deck get-seed` — the call an agent's extension (e.g. the bundled Pi extension) makes to pull its seed prompt natively at session start — asks the daemon for that prompt over the hook socket and previously had no read or write timeout of its own, relying entirely on the daemon closing the connection to know when to give up. A daemon that accepted the connection and then went completely silent without replying or closing it would leave `get-seed` waiting indefinitely.

The socket now has a 5 second idle timeout on reads and writes, and a timeout folds into the same "no seed" outcome as a daemon that closes without answering, so the pane falls back to the PTY-injection safety net instead of hanging. This is defence-in-depth rather than a fix for something observed: no user has hit the hang, since the daemon's line reader reacts promptly to EOF today. The change removes a latent failure mode, not an active one. It does not bound the total time a reply can take, so a daemon that keeps sending bytes without ever completing the reply line is not covered by this change; that gap is tracked separately.
