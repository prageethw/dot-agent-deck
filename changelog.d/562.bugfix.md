Fixes `worker-agent-deck`'s pane title and tool line rendering a raw control byte or Unicode bidi override (e.g. `U+202E` RIGHT-TO-LEFT OVERRIDE) sent through two seams that PR #558's display_name fix scoped out: an agent's `display_name` reaching `ui.display_names` unsanitized on hydration and rename, and a `ToolStart` event's `tool_name`/`tool_detail` reaching the card's rendered tool line unsanitized via the direct hook-socket ingest path. `display_name` is now scrubbed and length-clamped at the daemon-echo boundary and the rename gate now rejects Unicode format characters as well as raw control bytes. `tool_name`/`tool_detail` are now sanitized (control bytes and Unicode bidi/format characters) and length-clamped on the event itself at ingest, before it is journalled — the same seam the rendered tool line reads from — so the fix applies to what actually reaches the screen, not only to a separate internal copy. One consequence of the blanket rejection of Unicode format characters (`Cf`): renaming a pane to a name containing a ZWJ emoji sequence, a soft hyphen, or a stray BOM now silently does nothing, since the rename gate treats any `Cf` character as invalid input and returns a documented no-op rather than applying a partial rename.
