## The deck's attach protocol moves from 12 to 13, and agent commands from a `worker-agent-deck` built before this release are refused

This release merges this fork with upstream's current line. Both had reached protocol 12 on their own, and the two 12s were different wires, so the merged deck speaks neither and `PROTOCOL_VERSION` moves to 13. A TUI or desktop app from before this release and a daemon from this release refuse to attach to each other, in either direction, and say which protocol numbers they found. Upgrade the TUI, the desktop app and the daemon together.

`AttachRequest::WriteAndSubmit`, the attach request behind typed delivery, is withdrawn along with the `send_result` and `guarded_send` fields of its reply, so an older client that sends it gets a decode error. The hook verbs `delegate`, `work-done`, `wait start` and `wait done` now have to present the pane capability token the daemon puts in each agent's environment as `DOT_AGENT_DECK_PANE_CAPABILITY`, and a `worker-agent-deck` built before this release sends none, so the daemon refuses its message as `missing_token` for every pane it issued a token for. The token replaces this fork's own `generation` and `daemon_boot_id` identity keys on `delegate` and `work-done`, and the `--subject` flag is removed from both commands along with the daemon's cross-check between the two: a script that still passes it fails at argument parsing, so drop the flag.

**These refusals do not reach the agent that caused them, so reinstall `worker-agent-deck` BEFORE restarting the daemon.** An older `work-done` never reads the daemon's reply, so it exits 0 whatever happened, the worker's report is lost, and the orchestrator waits for it forever. `wait start` and `wait done` send without reading a reply either, so the only trace of a refusal is a `warn!` line in `deck.log`, the command exits 0, and the pane's `Working` marker never appears. Put the merged `worker-agent-deck` on `PATH` on every host that runs agents first. The merged TUI restarts an older daemon by itself when no agents run under it, so do this before you open it, then start your agents again.

`DOT_AGENT_DECK_HOOK_PROVENANCE=warn` on the daemon is a stop-gap for the gap between the two steps, not a setting to leave on. It admits a message that carries no token, with a warning in the log, which keeps an older `worker-agent-deck` working until you reinstall. It does that for every pane while it is set, so any process running as you that knows a pane id can again file a report or a delegation as that pane, which is the forgery the token exists to stop. A token issued for a different pane is refused either way. Unset it as soon as the binaries match.

**Why this is marked breaking.** The protocol number catches the pairings that handshake: the TUI and the desktop app against the daemon. The one-shot commands an agent runs inside its pane do not handshake, so nothing refuses them by version. Against the merged daemon an older `worker-agent-deck` still sends exactly the message it always did, and what changed is what the daemon does with a message that has no token. The same holds the other way: the merged commands add hook verbs an older daemon does not know, and run against one they fail without a version message. Install the commands, the TUI and the daemon from the same release.
