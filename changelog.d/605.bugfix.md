Fixes the new-pane form's same-cwd orchestration warning (PRD #140), which could not render in production for any directory since PRD fork#544 M2b made isolated-clone provisioning unconditional: a live orchestration's reported cwd is always a sibling workspace path derived from `(source directory, name)`, never the picked directory itself, so the warning's literal/canonical-only comparison never matched. `live_orchestration_in_same_cwd` now routes each `(cwd, name)` candidate through `live_orchestration_occupies` — the same directory-occupancy check fork#603's name-uniqueness feature already uses — so a live orchestration's real sibling-workspace cwd is recognized as occupying the picked directory again.

Fixed for a named orchestration; a live orchestration opened with a blank Name is a known, separate limitation the warning still misses (the comparison uses the display title rather than the segment the spawn path actually derives from, and the two diverge only when Name is blank) — tracked as follow-up #687, not addressed here. The warning's own copy is also known-stale post-fork#544 M2b (claims a shared working tree that no longer happens) — tracked as follow-up #688, maintainer decision on the remedy.

Pinned by `orchestration/guard/001` (`tests/render_orchestration_guard.rs`, rewritten to inject a live orchestration's real sibling-workspace cwd rather than a shape production can no longer produce) and `orchestration/guard/004` (a new direct-unit pin, `src/ui.rs`), both real tests.
