The orchestrator context injected by `build_orchestrator_context()` (`src/orchestrator_context.rs`) now teaches the orchestrator about the monitored-wait CLI from PRD #499 (`worker-agent-deck wait start <label>` / `worker-agent-deck wait done <label> --outcome <...>`) in its "## Important" section — before this, an orchestrator with a wait that genuinely spans turns (most often a delegated worker's response) had no way to know the CLI existed, since a project's own `.dot-agent-deck.toml` never mentions binary-level verbs, and fell back to constructing manual foreground polling loops instead.
