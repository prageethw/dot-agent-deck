The orchestrator context injected by `build_orchestrator_context()` (`src/orchestrator_context.rs`) now teaches the orchestrator about the monitored-wait CLI from PRD #499 (`{bin} wait start <label>` / `{bin} wait done <label> --outcome <...>`) in its "## Important" section — before this, an orchestrator waiting on an external result with no live foreground process of its own (a delegated worker's response, a CI run, an approval) had no way to know the CLI existed, since a project's own `.dot-agent-deck.toml` never mentions binary-level verbs, and fell back to constructing manual foreground polling loops instead.
