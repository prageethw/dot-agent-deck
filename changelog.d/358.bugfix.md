- **A worker's completion report can no longer land in the wrong orchestration's worktree**
  `handle_work_done` resolved a report's destination purely from the sender's bare `pane_id`, via `pane_cwd_map`/`pane_role_map` — the same maps `register_orchestration_role` overwrites whenever a pane_id is reused (a torn-down worktree's role pane recycled by a later, unrelated orchestration). A report produced under one registration but delivered after that pane_id was reassigned would silently land in the new tenant's worktree, under the new tenant's role label, and surface in the new tenant's orchestrator feedback — with the original sender's report simply gone. Every pane registration now carries a generation counter, and a report's daemon-verified generation must match the pane's current one before delivery; a stale report is refused (logged, not written) instead of misdelivered. Issue #358 is now closed.
