Fixes a Codex (and, structurally, any other `dot-agent-deck wrap`-launched agent) pane getting permanently stuck at `Working` after a normal turn. `wrap` always allocates a fresh PTY for the interactive agent process it spawns, so that primary child's POSIX session id differs from `wrap`'s own as an ordinary consequence of the spawn — the shell-activity monitor's descendant scan (PRD #386) mistook this for a detached background command still running, since the argv-shape veto that protects Claude Code panes from the same false positive was only ever measured for Claude. The resulting spurious `ShellBusy` event then clobbered a genuine, hook-confirmed `Idle` back to `Working` with no way to revert, since the OS-level scan can never observe a busy→idle transition for a pane that was never really busy. The descendant scan now recognizes a `wrap`-spawned pane's own direct child re-leading the fresh PTY session it was spawned into as expected topology, not evidence of detachment — while a genuinely detached descendant anywhere deeper in the tree, or a direct child of a non-`wrap` root (e.g. Claude Code's own real, `setsid`-detached Bash-tool child, which the fix must not — and does not — affect), still reads busy exactly as before.

No-Test: the regression this fixes is pinned by `wrap_primary_child_session_change_is_not_busy_but_a_deeper_detached_descendant_still_is` in `src/platform/proc/scan.rs`, a real test added ahead of this fix (TDD RED→GREEN) that exercises the exact failure and its guard against over-correction. It is not `#[spec]`-tagged: this fix task was explicitly instructed not to edit that tester-authored test in any way, including to add the tag, so R3's spec-test-delta check cannot see it. The existing `shell_busy_idle_promote_and_revert_without_clobbering_real_status` (src/state.rs) and `shell_activity_003`/`shell_activity_004` (tests/shell_activity.rs) regression tests were also re-verified to still pass, confirming no loss of coverage for the mechanisms this change touches.
