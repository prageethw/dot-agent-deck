Fixes a Codex (and, structurally, any other `dot-agent-deck wrap`-launched agent — today Codex is the only agent using that integration strategy) pane getting permanently stuck at `Working` after a normal turn. `wrap` always allocates a fresh PTY for the interactive agent process it spawns, so that primary child's POSIX session id differs from `wrap`'s own as an ordinary consequence of the spawn — the shell-activity monitor's descendant scan (PRD #386) mistook this for a detached background command still running, since the argv-shape veto that protects Claude Code panes from the same false positive was only ever measured for Claude. The resulting spurious `ShellBusy` event then clobbered a genuine, hook-confirmed `Idle` back to `Working` with no way to revert, since the OS-level scan can never observe a busy→idle transition for a pane that was never really busy. The descendant scan now recognizes a `wrap`-spawned pane's own direct child re-leading the fresh PTY session it was spawned into as expected topology, not evidence of detachment — while a genuinely detached descendant anywhere deeper in the tree, or a direct child of a non-`wrap` root (e.g. Claude Code's own real, `setsid`-detached Bash-tool child, which the fix must not — and does not — affect), still reads busy exactly as before.

A follow-up round closed two gaps the first pass left silently unfixed. First, the exemption originally only fired when the pane's own PTY child (`root_pid`) was itself the `wrap` invocation — but `wrap_launch_command`'s output is always multi-word, so the daemon always spawns it through `$SHELL -c '<wrap invocation>'`, never `wrap` directly; whether `root_pid` ends up being `wrap` or the surviving shell one hop above it depends on the shell and the exact command shape (dash never exec-optimizes, and `src/spawn.rs` pins `SHELL=/bin/sh` for every multi-word scheduler/issue-dispatch/orchestration-role command), so the original fix silently missed that whole topology. The scan now recognizes the `wrap` hop at whatever depth it actually sits, capped at one exemption per root-to-leaf path so a pathological multi-hop `wrap`-launching-`wrap` chain can't be exempted more than once. Second, the argv check that recognizes a `wrap` invocation now validates the command's own binary identity (reusing `wrap.rs`'s own basename check) rather than only matching the literal text `wrap` as the second word of any command — closing a spoofing gap where an unrelated pane command shaped `<anything> wrap …` got the exemption for reasons having nothing to do with this deck.

No-Test: the regression this fixes is pinned by `wrap_primary_child_session_change_is_not_busy_but_a_deeper_detached_descendant_still_is`, `wrap_spawned_via_a_surviving_shell_grandchild_session_change_is_not_busy_but_a_deeper_detached_descendant_still_is`, and `an_argv_that_merely_contains_wrap_as_its_second_token_must_not_exempt_a_detached_child` in `src/platform/proc/scan.rs` — real tests added ahead of each fix (TDD RED→GREEN) that exercise the exact failures and their guards against over-correction. None are `#[spec]`-tagged: both fix rounds were explicitly instructed not to edit tester-authored tests in any way, including to add the tag, so R3's spec-test-delta check cannot see them. The existing `shell_busy_idle_promote_and_revert_without_clobbering_real_status` (src/state.rs) and `shell_activity_003`/`shell_activity_004` (tests/shell_activity.rs) regression tests, plus `daemon::hook_ingestion_tests::shell_activity_monitor_ignores_a_pane_that_appeared_after_the_sample_started` (src/daemon.rs), were also re-verified to still pass, confirming no loss of coverage for the mechanisms this change touches.
