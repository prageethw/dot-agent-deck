## `worktree reclaim` can no longer auto-delete a pinned isolated clone

Fork issue #546's Hazard 2: M4c's automatic reclaim judged an isolated clone solely on provenance and content safety — owned by this deck, clean, a single local branch, no stash, HEAD matching a merged PR's `headRefOid` — with no way to say "keep this one anyway." A clone satisfying all five of those conditions could be deleted by `worktree reclaim --yes` even while someone was deliberately still resuming it by name.

An isolated clone can now be pinned against automatic reclaim, and unpinned again, independently of all five existing conditions — a pinned clone is never reported reclaim-eligible and is never removed by `worktree reclaim`, bare or with `--yes`, regardless of how many of the other five conditions it satisfies. Pin/unpin ships as a tested primitive in this release; CLI wiring to set the pin is a fast-follow-up.
