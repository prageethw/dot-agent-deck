Fixed a pane reading **Working** forever after you reconnected to the deck while a shell command was still running in it. The daemon promotes a pane to `Working` on its own while a foreground shell command runs, and demotes it again when the command finishes. If the TUI reconnected in between, two things went wrong on the reconnect path: the card was restored from the daemon's snapshot without the marker that records *why* it was `Working`, so the paired finish signal declined to revert it; and the finish signal could not reach the reconnected card at all, landing on a second, phantom card beside it instead. A pane in that state stayed `Working` until something unrelated happened to it.

The reconnected card now keeps that provenance and returns to `Idle` when the command finishes. A card whose `Working` came from a real agent event is still never reverted by the shell signal, and the agent the signal belongs to is resolved from the pane's own card — so it still lands correctly after a `/clear` or thread restart, which rolls the pane's session generation forward while the card keeps its stable identity.
