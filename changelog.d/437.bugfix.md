- **The orchestration dashboard no longer silently drops role cards on a narrow-and-short terminal**
  `grid_columns` (width-only) and `choose_density` (height-only, given a fixed column count) each decided their own axis independently, so neither could compensate for the other. On a terminal that was both narrow and short — the reported case was 7 roles, width under 100 columns, ~30 usable rows — `grid_columns` never considered more than 1 column, no density fit at 1 column, and the render silently sliced to whatever fit: 5 of 7 cards painted, 2 never drawn, with nothing on screen indicating it. A hidden role read as a dead worker.

  `fit_grid` now searches columns and density jointly, starting from the same column count `grid_columns` would already have picked for the terminal's width and only searching for a different count when that doesn't fit — so an ordinary wide terminal keeps exactly the layout it had before, and only the narrow-and-short case that used to lose cards actually changes. The reported case now resolves to 2 columns at Compact density, and all 7 cards render. `ui.columns` is now written from the same value the render path actually used, rather than a value computed independently that could go stale relative to what was drawn — nothing in the app currently reads `ui.columns`, so this is dead-state hygiene rather than a fix to any observable behavior. When a tab has more role cards than fit in the current viewport, the dashboard title now shows how many are scrolled out of view instead of staying silent about them.

  Tracks upstream vfarcic/dot-agent-deck#588. Issue #437 is now closed.

  Covered by `dashboard/grid/001`–`003` (`src/ui.rs`, `#[spec]`-annotated TestBackend render tests), plus plain `#[test]` unit coverage for the internal `fit_grid`/`max_cols_for_width` pure-data functions.
