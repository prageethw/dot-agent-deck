- **`resolve_orchestration_name`'s whitespace-only guard was re-examined and reaffirmed, and now has direct test coverage (no functional change)**

  Fork issue #174 asked whether `resolve_orchestration_name` should guard on `.trim().is_empty()` instead of `.is_empty()`, so a whitespace-only orchestration name (e.g. `name = "   "`) falls back to the directory basename like an empty name already does. That guard was tried and reverted before this fix: PR #274 added the trim, then removed it on review, because `TabMembership::Orchestration.name` crosses the TUI↔daemon wire, and changing what a whitespace-only name resolves to is a same-wire, different-meaning break under CLAUDE.md rule 12 — the defect has no known occurrence, so the compatibility cost (a `changelog.d/*.breaking.md` fragment and, if the wire shape itself moved, a `PROTOCOL_VERSION` bump) was judged not warranted. That decision stands unchanged here. What was missing was a regression test pinning it at the source: the guard's own test module explicitly noted the whitespace case was "not covered here," leaving the decision pinned only by a consumer-level test in `state.rs`. Two new tests close that gap directly on `resolve_orchestration_name`, and the doc comment now points to them.

No-Test: covered by new plain `#[test]`s (`resolve_orchestration_name_treats_whitespace_only_name_as_present`, `resolve_orchestration_name_does_not_trim_surrounding_whitespace`) in `src/project_config.rs`'s `mod tests`, not `#[spec]`-annotated — this is internal guard coverage with no user-visible scenario to narrate, and no production behavior changed.
