The New Pane form's orchestration branch gets its "Worktree slug" field back: an optional, short, human-typed identifier that names the isolated-clone workspace directory and branch, separate from the descriptive orchestration "Name" you type. Tab from Name to reach it once an orchestration is selected.

This changes what a blank slug does. On every released build since fork#544, a fresh open with the slug left blank derived the workspace directory from your typed Name. From this change on, a blank slug instead auto-generates `orchestrator-N`, completely independent of Name — restoring the pre-fork#544 behavior, not preserving the one you've been running. **There is no automated way to resume an existing fork#544-era workspace through this field.** Typing its old Name into the new Worktree-slug field does not reliably work: the field validates against a strict allowlist (letters, digits, `-`, `_`, and it must start with a letter, digit, or `_`) that most free-text Names fail outright, and even a Name that happens to pass validation won't resume the old workspace — its on-disk ownership marker was derived from the Name itself, and this field's marker derivation no longer reconstructs that value. If you still need an existing fork#544-era workspace, find it manually — it is a sibling directory next to your repo checkout, named `<repo-basename>-<sanitized-old-Name>` — and either keep working in it directly (point your shell/editor at it) or migrate what you need out of it. Leaving the slug blank on a fresh open of that same orchestration creates a brand-new `orchestrator-N` workspace alongside the old one rather than finding it.

Type a slug (e.g. `fix-544`) and it — not the potentially long, descriptive Name — becomes the workspace's folder/branch name, while Name keeps doing its own job: the tab title and the daemon-side uniqueness check that stops two orchestrations from colliding under the same Name.

Reopening under the identical slug resumes the same on-disk workspace rather than creating a new one, regardless of what Name you type this time — the slug alone decides which workspace this is, so retyping the Name never blocks a resume with a false "already open under a different name" refusal.
