Every orchestrator's startup context (fresh spawn and every resume via compaction/`/clear`) now carries a framework-generated "Workspace sync" section, ahead of "Available agents" and "Delegation protocol" (issue #760 Part B). It directs the orchestrator to check its mapped workspace for uncommitted, staged, or untracked changes before touching anything else, and — if it finds any — to report what is dirty, skip the fetch/merge for this pass, and continue straight into normal orchestration rather than fetching or merging over it. Once confirmed clean, it fetches the repository's default branch non-interactively, resolves the actual default branch name rather than assuming `main`, and merges it in if the workspace is behind — clarifying that `worktree sync` itself does not do this (it only fast-forwards a workspace onto the default branch once that workspace's own work has already merged). A missing `origin` remote, or a branch with no configured upstream, are both treated as expected rather than something to "fix" by re-adding a remote or setting one. Destructive recovery commands (`git reset --hard`, `git clean -f`/`-fdx`, `git checkout .`/`-f`, `git restore .`, and others that can discard work) are explicitly forbidden as a way to force the sync through, and a merge conflict is aborted back to a clean state before the orchestrator stops to report it, rather than left half-merged.
