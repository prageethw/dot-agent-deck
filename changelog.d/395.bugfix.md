Fixed a torn-frame race in the PTY e2e test harness that had turned `e2e_scheduler_manager::form_002_add_spawns_authoring_agent_in_picked_dir` from intermittently flaky into a reliable CI failure. Many e2e tests located a widget by first waiting for an unrelated proxy string to appear in the terminal grid, then taking a single instantaneous `find_in_grid` snapshot and expecting the widget to already be there. The deck writes a rendered frame in one burst, but the harness reader feeds the vt100 parser in `read()`-sized chunks — as little as ~1 KiB per read on macOS PTYs — so a frame taller than one chunk is briefly visible as a legitimate but torn grid: the proxy string can already be painted while the widget the test actually wants has not been parsed yet. That window is around 0.15ms locally but widens into milliseconds on a contended CI runner.

50 call sites across 19 `e2e_*.rs` files now use the existing `TuiDeck::wait_for_in_grid` helper, which polls until the needle itself appears and returns its coordinates — so the wait is on the widget that supplies the click coordinates, not on a proxy string that can render first. No assertion was removed and no harness or production code changed; this is a synchronisation fix in test code only.
