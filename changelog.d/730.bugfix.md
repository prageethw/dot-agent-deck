A wrapped agent's fork-time `SessionStart` — the card-surfacing signal `dot-agent-deck wrap` sends the instant it spawns the wrapped child, seconds before that child has done any real work — could also prematurely mark a pane's `session.agent_type` as known, before the wrapped agent had identified itself. That defeated the dashboard's "Starting…" readiness gate (`is_untyped_agent` / `is_pending` in `render_session_card`), so a Codex-backed pane whose native hooks hadn't fired yet could fall through to a stale leftover status (e.g. "Thinking") shown indefinitely instead — issue #730's reported symptom. `AppState::apply_event` no longer sets `session.agent_type` from an event whose `AgentEvent::is_wrapper_fork_session_start()` is true; the wrapper's later interface-ready/settled signals, which genuinely observe the wrapped child doing something, are unaffected and still resolve `agent_type` as before.
