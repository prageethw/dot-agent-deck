- **The command-entry lock now works regardless of where the deck is launched from**

  The `Ctrl+D` → `Ctrl+E` orchestrator-editability lock was gated behind the `experimental` feature flag, which resolves from a `.dot-agent-deck.toml` walked up from the process's current directory. The deck is a multi-project dashboard normally launched from `$HOME`, where no such file exists above it — so the flag silently resolved OFF and the lock was completely absent in normal use: `Ctrl+E` claimed nothing, keystrokes reached a focused worker pane untouched, and no automatic focus movement happened.

  The lock no longer depends on the flag. It is always on, exactly as it was designed to be before the flag was added after the fact.
