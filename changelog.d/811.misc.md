## Tests: the kept-worktree preview probe-timeout test no longer races a 1-nanosecond deadline

`kept_worktree_preview_still_reports_the_path_when_the_probe_times_out` gave the probe a `Duration::from_nanos(1)` deadline and asserted that it timed out, so it failed whenever the probe happened to finish first. The test now hands the preview a probe stand-in that never answers, so the deadline is the only way the wait can end and the timeout happens by construction. The stand-in goes in through a private `kept_worktree_preview_with` seam that production calls with the real `git status` probe, so no product behaviour changes.
