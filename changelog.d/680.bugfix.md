Fixed a deterministic failure in the orchestration remit re-assertion test suite that had been failing on every run of `main`'s e2e tier (issue #680). The test covering "a compaction re-assertion preserves a dispatched task's context" was reading and writing the orchestrator's `.dot-agent-deck/orchestrator-context.md` file at the wrong location — a stale path left over from before orchestrator-role workspace isolation became unconditional (PRD #544), when the file still lived in the fixture's own directory rather than the orchestrator's isolated clone. The test now reads and writes the context file at the same isolated-clone path the orchestrator role pane and the daemon actually use, matching every other test in the same file that already made this same isolation-aware adjustment.

No production behavior changed: the orchestrator's context-file handling and task-preserving compaction re-assertion were working correctly the whole time. This was a test-only fix that removes a false-negative e2e signal, restoring real coverage for the "a dispatched task survives a compaction re-assertion" guarantee.
