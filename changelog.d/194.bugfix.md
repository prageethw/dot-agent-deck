- **A confirmation retry no longer re-types the whole prompt**

  When the orchestrator's role prompt, a mode seed prompt, or a spawn-time dispatch prompt landed on the pane but the agent had not yet reported the submission back within the retry backoff (~500ms), the delivery path re-typed the entire prompt into the pane a second time. The submit keypress may have been swallowed by a still-booting agent TUI, but the payload itself had already reached the composer, so retyping it produced a doubled prompt visibly sitting in the pane rather than recovering the missed submit.

  A retry now only probes submission on the pane's existing input after the first attempt — it asks the agent's TUI to submit what it already holds instead of writing the prompt again. This restores the fork's original fix for issue #194 (PRD #197 M4), which the 2026-08-15 upstream sync silently dropped.
