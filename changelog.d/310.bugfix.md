- **A swapped features-config target can no longer hang deck startup**

  `load_features_file` used to stat the target and then open it as two separate steps. Between them the target could be replaced, and if the replacement was a FIFO, opening it blocked indefinitely waiting for a writer — on the synchronous startup path, before the watcher thread even exists. The loader (and its diagnostic mirror used by `features status`) now opens the target first, non-blocking on Unix, and validates the same handle it opened, so there is no window between the check and the use and a FIFO is rejected immediately instead of blocking. On Windows, opening a directory target now requests backup semantics so it still reports as non-regular instead of unreadable, matching prior behavior there.

No-Test: this is a pure-data fix to the shared open-then-validate loader, covered by the existing FIFO regression test in `src/config.rs`'s `mod tests`. The TOCTOU race itself can't be reproduced deterministically from a test — the window is a handful of instructions between two syscalls — so that test pins the fix's load-bearing half (a FIFO target no longer hangs startup) rather than the race itself.
