Fixed `write_atomic` in `codex_hooks_manage.rs` silently widening the permissions of `CODEX_HOME/hooks.json` and `CODEX_HOME/config.toml` every time the deck published to them. The temp file it wrote before renaming over the destination was created with `File::create`, which on Unix gets `0666 & !umask` — typically `0644` — regardless of the destination's existing mode; `rename(2)` then replaces the destination's inode outright, so a file the user had deliberately kept restrictive (e.g. `0600`) was widened on the very first write, and stayed widened on every subsequent one since nothing repaired it afterwards. Because `install_to`/`uninstall_from` run automatically whenever `codex` is on `PATH` (Codex startup auto-install), and `edit_trust_state` runs against the user's real `config.toml`, this could widen a private config without any explicit action from the user.

`write_atomic` now sets the temp file's mode to the destination's own mode (masked to `0o777`) when the destination exists, or `0600` for a new file — mirroring the fix already in place for Devin's equivalent `write_atomic` in `devin_hooks_manage.rs`.
