## `cargo xtask linkage-check` now catches a resurrected changelog fragment before it ships

Issue #259 catalogued eight rebase artifacts that a PRD #197's rebase across the 2026-08-12 upstream sync silently resurrected — content `main` had already deliberately moved on from. Seven were caught by ad-hoc means (CI failing to parse, `cargo xtask linkage-check`'s existing checks, the compiler, a reviewer reading by hand); the eighth, `changelog.d/163.bugfix.md`, was not caught until after merge (issue #258) because its content had already been consumed into `CHANGELOG.md` at v0.37.1 and nothing compared an added fragment's body against what the changelog already carried.

`linkage-check` gains an eleventh check: every `changelog.d/*.md` fragment added by a branch (versus `origin/main`) now has its content compared against `CHANGELOG.md` at the branch's merge-base with `origin/main` — what `origin/main` actually shipped, not what the branch's own `HEAD` currently claims, so a branch that resurrects a fragment and also rewrites `CHANGELOG.md` in the same diff cannot escape the check. A fragment whose body already appears there — even after a rebase reformats it with different indentation or drops the blank line between paragraphs — fails the check by name; a fragment with genuinely new content, however similarly worded, passes. The comparison is deliberately exact-text (whitespace-normalized, not fuzzy) with a minimum-length floor, so a fragment that merely shares a few words or a topic with an old entry, or coincidentally matches a short generic sentence, is never flagged. An unresolvable base (no `origin/main`, not a git repository at all) is a printed skip, not a hard failure, matching the existing repository-state preflight's own polarity.

This closes only the one artifact from #259's table that actually reached `main` — the fragment-resurrection shape, which is mechanically precise with no false-positive risk. The broader "why does this branch touch this file at all" heuristic #259 also raises, covering the other seven artifact kinds, is left as explicit future work; those already have gates elsewhere (CI structure, this file's other checks, the compiler).

No-Test: pinned entirely by plain `#[test]` functions in `xtask/linkage-check/src/work_type.rs`'s `mod tests` (`check_resurrected_fragments_flags_a_fragment_whose_body_already_shipped` and siblings for the core match, `check_resurrected_fragments_flags_even_when_head_rewrites_changelog` for the base-vs-HEAD comparison target, `check_resurrected_fragments_flags_a_fragment_introduced_by_rename` for the rename path, `check_resurrected_fragments_does_not_false_positive_on_a_near_miss` and `check_resurrected_fragments_does_not_flag_a_match_below_the_min_body_length` for the two false-positive guards) plus an integration test driving the compiled binary in `xtask/linkage-check/tests/resurrected_changelog_fragment.rs` — not `#[spec]`-annotated ones, since `xtask/**` is a build-time linting tool, not TUI-observable behavior, matching `399.bugfix.md`'s and `468.bugfix.md`'s precedent for the same class of change in this same crate.
