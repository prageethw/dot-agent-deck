Fixes four fixture/scratch-repo git-invocation helpers that PR #663 (issue #579) missed neutralizing git's location- and config-discovery environment variables in: `xtask/linkage-check/src/work_type.rs`'s `#[cfg(test)]`-only `git()` fixture helper, `xtask/linkage-check/src/work_type.rs`'s **production** `run_git()` — the one `init_self_test_repo` and `--self-test` actually call, 21 call sites — `xtask/linkage-check/tests/resurrected_changelog_fragment.rs`'s copy of the same fixture helper, and `tests/release_cleanup.rs`'s `run_git()` (used by the `cleanup.sh` fixture suite, now split into a `Result`-returning `try_run_git()` plus a panicking `run_git()` wrapper). Each previously neutralized only `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM`, only `GIT_DIR`/`GIT_WORK_TREE`, or (the production helper) nothing at all on this axis — the same read/write escape shape #579 fixed in `repo_state.rs`'s `Sandbox::git()`, reachable from the same pre-commit-hook/`git rebase --exec`/`git bisect run` contexts, and reproduced as a destructive rewrite of a real repository's `refs/remotes/origin/main` via the production helper.

All four now close the full location-var list — `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_NAMESPACE` — plus two previously-open config-injection vars, `GIT_CONFIG_PARAMETERS`/`GIT_CONFIG_COUNT` (git accepts config values, including `core.hooksPath`, directly from these, bypassing `GIT_CONFIG_NOSYSTEM`/`GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM` entirely — reproduced as pre-commit hook execution). The three helpers that `env_remove` rather than bind `GIT_CEILING_DIRECTORIES` (every fixture command they run always targets an already-initialized repo or an init/clone target, never a walk that could resolve past `cwd` into nothing) also now clear `GIT_DISCOVERY_ACROSS_FILESYSTEM`, one of the only two things that bounds an otherwise-unbounded upward walk. `tests/release_cleanup.rs`'s `run_git()`/`try_run_git()` instead binds `GIT_CEILING_DIRECTORIES` to the target directory's parent (canonicalized, falling back to the uncanonicalized path) — a new, stricter policy for this file, not an application of the same file's `run_cleanup` precedent (which bounds at the OS temp dir, not the target directory): a directory that is not itself a repository must fail discovery closed at that directory instead of silently resolving a real repository somewhere above it. It also now sets `GIT_CONFIG_GLOBAL=/dev/null`, closing a previously-open channel where the invoking developer's or runner's own `$HOME/.gitconfig` (a `core.hooksPath` above all) applied inside every fixture `git` invocation.

No-Test: the regression is pinned by `git_test_helper_leaks_ambient_git_dir_and_git_work_tree` in both `xtask/linkage-check/src/work_type.rs` and `xtask/linkage-check/tests/resurrected_changelog_fragment.rs`, `production_run_git_leaks_ambient_git_dir_and_git_work_tree` in `xtask/linkage-check/src/work_type.rs`, and `release_cleanup_028_run_git_leaks_ambient_git_index_file`/`release_cleanup_029_run_git_does_not_bound_upward_discovery_with_git_ceiling_directories`/`release_cleanup_030_run_git_leaks_ambient_git_config_count_hook_execution`/`release_cleanup_031_run_git_leaks_ambient_home_gitconfig_hook_execution` in `tests/release_cleanup.rs` — real tests (RED before this fix, GREEN after), not a documentation gap.
