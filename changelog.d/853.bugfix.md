## Two orchestrations can no longer open under one name in one project, and `work-done --task-file` accepts a report file at the summary path

Opening a new orchestration run checks that no other live run in the same project already has that name. Because the deck runs each orchestration in its own isolated clone of the project, that check compared the clone's directory, so a second client that named the project's own directory (the desktop app, or another deck window opened before the first submitted) was never matched and both runs opened under the same name, as two tabs you could not tell apart. The check now compares the directory a clone was made from, so the second run is refused with the usual "name already in use" message (in the deck's own form it reopens with that warning). Only the uniqueness check changed: where the agents run and what they record is unchanged, and a start that names a project directly is checked exactly as before.

`work-done --task-file <path>` no longer refuses a file inside `.dot-agent-deck/` that is named like a summary (`work-done-<role>.md`). The refusal existed so that the deck's own summary could not overwrite the very file being reported; the deck now enforces that itself. It replaces its summary file only when the file is empty or is one the deck wrote, keeps any other file byte for byte (a symlink at that path is refused rather than followed), and saves the report under a fresh `full-report-work-done-<role>-*.md` name instead. The orchestrator still receives your report, and the file you wrote is left as it was.
