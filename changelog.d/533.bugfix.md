Fixes `remove_isolated_clone_dir`'s removal-time re-verification calling `resolve_pr_state` directly against an isolated clone's own (untrusted) `origin`, with no slug-equality guard, unlike `isolated_clone_report`'s examination-time check — a follow-up finding from PR #526's (fork issue #325 M4c) final reviewer+auditor confirmation pass (reviewer N4, auditor N1). A same-uid actor could repoint a candidate's `origin` at an attacker-controlled repo slug between examination and removal, letting a `gh` reply resolved against that attacker slug drive a merged-PR removal decision — bounded in impact, since the delete target itself is fixed at examination time and a defeated re-check can only fail to *prevent* an already-authorized delete, never redirect it. `remove_isolated_clone_dir` now takes `root_repo_slug: Option<&str>` as its third parameter and refuses before ever calling `resolve_pr_state` unless the candidate's own derived repo slug still equals the root checkout's own, mirroring `isolated_clone_report`'s guard exactly; `run_reclaim` derives the root checkout's own slug once and passes it at its one real call site.
