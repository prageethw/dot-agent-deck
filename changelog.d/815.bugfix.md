## A pi-native worker that exits before replying no longer leaves the orchestrator reading `Observing`

A `delegate` with `clear = true` to a pi-native worker returned before recording the replacement worker's agent id on the delegation. If that replacement exited before sending `work-done`, the daemon could not match the exit to the delegation, so the worker's card read `Idle (delegated)` and the orchestrator's read `Observing` until `worker_response_timeout_minutes` ran out, and only then did the orchestrator get an idle-worker prompt about a worker that was long gone. The agent id is now recorded on the pi-native path as it already was on every other path, so the delegation is retired when the worker exits: both cards return to `Idle` straight away, and the orchestrator's pane gets the "exited without work-done" notice at that moment instead of the late prompt.

A replacement that is already gone by the time its task would be handed over is reported the same way, once, and is no longer counted as owing a completion for a task it never received.
