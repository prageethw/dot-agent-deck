## `work-type-check` no longer forces a breaking bugfix into the `prd` classification

`cargo xtask work-type-check` (the CI gate that derives a PR's work type from its changelog fragments and branch name) treated `breaking` as a work type of its own, mapping every `.breaking.md` fragment straight to `prd` regardless of branch. That meant a genuine breaking bug fix — a `.breaking.md` fragment on a `fix/`-prefixed branch — always failed the gate with `FragmentBranchDisagree`, even though `docs/develop/work-types.md` documents `breaking` as a severity axis, not a fifth work type: "a `bug` fix can be breaking, and so can a `prd`."

`.breaking.md` fragment resolution is now branch-aware. On a `fix/` branch it resolves to `bug`; on a `feat/` branch, or when the branch carries no recognized work-type prefix at all, it still resolves to `prd` exactly as before. A `.breaking.md` fragment paired with a `docs/` or `chore/` branch still fails as a genuine mismatch, and a mix of `.breaking.md` and non-`breaking` fragments resolving to different work types still fails as `ConflictingFragments` — only the single-axis `breaking` + `fix/` combination changes.

No-Test: the four new regression tests (`breaking_fragment_on_fix_branch_resolves_to_bug` and siblings in `xtask/linkage-check/src/work_type.rs`) are plain `#[test]`s in the `xtask/linkage-check` crate, which does not use the `#[spec(...)]` TUI-catalog convention `work-type-check`'s own R3 rule looks for — that convention is specific to the main `dot_agent_deck` crate's test harness (CLAUDE.md rule 4/7) and does not apply to this xtask crate's plain unit tests.
