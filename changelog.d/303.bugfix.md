- **A deck launched outside a project directory now says so**

  When `dot-agent-deck` was launched from a directory with no `.dot-agent-deck.toml` anywhere above it (e.g. from `$HOME`), every experimental surface silently resolved OFF with no visible signal — the only trace was a `tracing::info!`/`tracing::warn!` pair gated behind `DOT_AGENT_DECK_LOG`, which took `lsof` and log-file archaeology to find.

  The deck now prints a warning to stderr on startup when this happens, visible with no `DOT_AGENT_DECK_LOG` and no restart, and stays completely silent when a config is found. A new `dot-agent-deck features status` subcommand also reports, on demand and whether or not the deck is running, the resolved config path, whether it exists, the resolved value, and which source won (env override, project file, or default).
