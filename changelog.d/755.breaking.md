## Attach-protocol bump: live delegation-status push (`PROTOCOL_VERSION` 11 → 12)

**Wire-shape change.** Closing issue #755's own primary scenario — a dashboard pane you are watching live, with no reconnect, whose delegated-worker status the badge/bell/aggregate-count never updated for — needed the daemon to push the change the instant it happens, not just at hydration or reconnect. The daemon→TUI event broadcast (`BroadcastMsg`, forwarded over the attach socket's `KIND_EVENT` frame) gained two new variants, `delegation_armed` and `delegation_retired`, carrying the worker pane id (plus, for the armed case, the same `WatchSnapshot` `worker-agent-deck daemon status` already surfaces). That is a wire-shape change an older peer would fail to deserialize, so `PROTOCOL_VERSION` bumped from 11 to 12 and the attach handshake refuses across the mismatch — the same reason `OrchestrationSurface` (3 → 4) and `WorktreeKept` (7 → 8) bumped before it.

Compatibility impact: a TUI and daemon must be on the same `PROTOCOL_VERSION` to interoperate. The daemon deliberately outlives the TUI, so after upgrading in place an older still-running daemon and the new TUI will fail the handshake until the daemon is restarted (the standard recovery the build-version handshake already prompts for). Hook events, the single-agent live-surface path, `OrchestrationSurface`, and `WorktreeKept` are unchanged. The failure mode is a clean, actionable refusal at attach time, never a partial or corrupted event stream: `BroadcastMsg` carries no `#[serde(other)]` catch-all, so a skewed pair would otherwise fail per-frame instead — the version check exists precisely so that never happens in practice.

Prose in this fork calls the product `worker-agent-deck`; the binary name in a command you would actually paste and run is still `dot-agent-deck`.
