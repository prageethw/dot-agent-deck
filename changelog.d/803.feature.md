## An orchestrator waiting on delegated workers now reads `Observing` automatically

An orchestrator that has delegated work and is waiting for a worker's `work-done` used to read plain `Idle` unless the orchestrator agent itself remembered to run `worker-agent-deck wait start`. The TUI and `worker-agent-deck daemon status` now each work this out from the delegations the daemon already reports: while an orchestrator pane is `Idle` and at least one delegation it issued is still outstanding, it reads `Observing` on the deck card and in the `daemon status` table. This is a label only — the pane's status is still `Idle`, `--json` keeps `"status": "Idle"` and reports the new, always-present `observing_delegations` field as `true`, and the existing `wait_observing` field keeps its meaning. It reverts when the last of those delegations is retired, including by the idle-worker timeout (`worker_response_timeout_minutes`, 2 hours by default); it is not bounded by the monitored-wait TTL. With `worker_response_timeout_minutes = 0` the daemon records no delegations, so the label never appears. A pane that itself still owes a `work-done` is shown as a delegated worker, never as `Observing`.

One thing to be aware of: an orchestrator that delegates and then stops to ask you something in plain text is `Idle` underneath and will read `Observing` until its workers report back. `bell.on_idle` still rings for it.

`worker-agent-deck wait start` / `wait done` are unchanged and remain the way to declare a wait the daemon cannot know about, such as CI or an approval.
