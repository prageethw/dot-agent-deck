## An orchestrator waiting on delegated workers now reads `Observing` automatically

An orchestrator that has delegated work and is waiting for a worker's `work-done` used to read plain `Idle` unless the orchestrator agent itself remembered to run `worker-agent-deck wait start`. The daemon now derives this from the delegations it already tracks: while an orchestrator pane has at least one outstanding delegation it issued, and nothing else (a pending prompt, an error, real agent activity) says otherwise, it reads `Observing` on both the `worker-agent-deck daemon status` table (and its `--json` `wait_observing` field) and the TUI deck card. It reverts when the last of those delegations is retired, and is not bounded by the monitored-wait TTL.

`worker-agent-deck wait start` / `wait done` are unchanged and remain the way to declare a wait the daemon cannot know about, such as CI or an approval.
