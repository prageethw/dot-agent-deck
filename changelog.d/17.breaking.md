## Local daemon attach now enforces `PROTOCOL_VERSION`

The TUI↔daemon attach protocol version was only checked on the SSH/`remote add` path — the local (same-machine) attach never inspected it. A daemon started by an older or newer binary than the one attaching would connect successfully anyway, and the dashboard looked completely normal while every event the TUI could not decode was silently dropped and the subscription reconnect-looped invisibly.

Local attach now compares the daemon's advertised protocol version against the version this binary speaks, before any other startup decision is made, and refuses to attach on a mismatch instead of connecting silently. The refusal names both protocol versions and the running daemon's build, says how many agents are running under it, and gives two ways forward:

```
error: local daemon speaks attach protocol v8 but this binary speaks v7
   running daemon:  0.36.0-g1111new

   Refusing to attach. Across a protocol skew the dashboard still looks
   normal while every event this binary cannot decode is silently dropped.
   2 agent(s) are running under it.

recover with: dot-agent-deck daemon stop   (stops the daemon and any agents
   under it), then relaunch — the next launch starts a fresh daemon at this
   binary's protocol version.
   To keep those agents instead, relaunch using the daemon's own build
   (0.36.0-g1111new) rather than stopping it.
```

**This is a breaking change for one specific pairing that used to work:** an older daemon with a newer TUI, where the user declined a restart, used to attach successfully — safely, since an older daemon cannot emit event variants a newer TUI doesn't understand. That pairing is now refused too. The check is deliberately unconditional rather than one-directional, because "safe in one direction" is an accident of which variants a particular version bump happened to add, not a guarantee the protocol makes for future bumps. If you hit the refusal and want to keep agents running under an older daemon, relaunch on that daemon's own build rather than stopping it; otherwise `dot-agent-deck daemon stop` and relaunch to start a fresh daemon at the current protocol version.

The wire protocol itself is unchanged — `PROTOCOL_VERSION` stays at its current value. This adds a check against the existing constant; it does not move the wire.
