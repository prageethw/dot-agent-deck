## An orchestrator is reminded of its role after its context is compacted

An orchestration role is told what it is exactly once — a seed prompt sent when its pane starts. Nothing ever says it again. So in a long session the remit gradually stops being present: the agent still has the project's own instructions, which its harness re-injects on every turn, but the one sentence saying *you coordinate, you do not implement* has quietly aged out of the conversation. Adherence decays with session length, and it decays worst exactly when an orchestration is long and complicated, which is when the roles matter most.

The failure this closes was not a misunderstanding. An orchestrator whose remit said, in as many words, that it never does implementation work itself sat down and wrote a test file rather than delegating it — several hours into a session that had been compacted. Nothing was ambiguous and nothing was ignored; the instruction simply was not there any more. The gradient is also smooth enough that there is no obvious moment of crossing a line: closing an issue, editing a document, writing a changelog and writing a test file are each a small step from the last, and the first three are genuinely the orchestrator's job.

The deck now watches for the moment that causes the loss. When an orchestration's start role reports that its context has been compacted, the deck re-sends the same one-line pointer to that role's context file that it sent at spawn — the file itself is already on disk and unchanged, so this is a reminder rather than new instruction. Re-assertion goes through exactly the same delivery machinery as the original seed, including waiting until the pane is ready to accept input and confirming the prompt was genuinely submitted, so it cannot land as a stray line in an agent's input box.

Only the orchestration's start role is re-reminded, and only on compaction. A worker role is not, because a worker's remit has no equivalent file behind it to point at. Nothing is re-sent on a timer, and a re-assertion is never attempted while a previous delivery to that pane is still in flight, so a busy or unreachable pane is left alone rather than accumulating queued prompts. A role that has already finished or failed keeps that status instead of being flipped back to working.

This addresses the decay, not the underlying design. The remit is still delivered as a one-time message rather than something the agent re-reads each turn, and compaction is the only event that triggers a reminder — a session that runs long without ever compacting will still drift.
