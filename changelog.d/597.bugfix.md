- **`worktree pin`/`worktree unpin` are now wired to the CLI, and `worktree list --json` reports whether an isolated clone is pinned**
  Fork issue #546's pin/unpin exemption from `worktree reclaim`'s automatic removal shipped as a tested library primitive, but with no CLI wiring — the only way to pin or unpin an isolated clone was to call `pin_isolated_clone`/`unpin_isolated_clone` directly from Rust. `worktree pin <path>` and `worktree unpin <path>` now expose that primitive as ordinary subcommands, synchronous and daemon-free like `worktree list`/`worktree reclaim`; a `worktree pin` against a path with no provenance artifact (a linked worktree, not an isolated clone) fails cleanly with a non-zero exit and a stderr message rather than crashing or fabricating one.
  `WorktreeReport` also gained a `pinned` field, always present in `worktree list --json` for every row: `true` for an isolated clone that is explicitly pinned or whose pin state could not be read (failing closed, matching the reclaim-eligibility gate's own existing treatment of an unreadable pin signal), `false` otherwise — including every `"linked"`-kind row, where pinning does not apply.
  Also fixes a same-process temp-file collision in the underlying rewrite: `set_isolated_clone_pinned`'s temp-file suffix was `std::process::id()` alone, so two concurrent pin/unpin calls against the same clone within one process could collide on an identical temp path and publish a torn write. It now uses a per-process nonce+sequence disambiguator (the same recipe `mint_pane_id`/`next_pane_id` already use), guaranteeing two calls from the same process never produce the same suffix.
