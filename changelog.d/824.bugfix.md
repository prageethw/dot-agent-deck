## After a session restore, keyboard focus lands on the pane the tab started with, not a random one

Restoring an orchestration tab from a snapshot focuses "the first restored pane" and enters pane-input mode so you can type straight away. The deck listed its panes by sorting their ids as numbers, but pane ids are now minted as `pane-<hex>-<n>`, so no id parsed as a number and the order came out arbitrary, different on every run. Focus (and whatever you typed or pasted next) could land on any role's pane instead of the start role's. The deck now keeps panes in the order they were created and restore focuses the start role's pane explicitly.
