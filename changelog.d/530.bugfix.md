## The identity-guarded write primitive can no longer fail open on a missing agent identity

`AgentPtyRegistry::write_guarded` and its three public entry points (`write_and_submit_guarded`, `write_and_submit_guarded_detailed`, `write_notice_guarded`) took `expected_agent_id: Option<&str>`, and silently skipped the pre-lock identity check whenever a caller passed `None` — an unguarded write to whoever currently owned the pane. This was the root cause behind three prior bugs (issue #465/PR #477, issue #492, issue #494/PR #523), each fixed by hand-rolling a `let Some(..) else { refuse }` guard at one more call site rather than closing the gap at its source.

`expected_agent_id` is now a plain `&str` on all four functions: a caller with no resolved identity can no longer even compile a call to them, so the fail-open path is closed for every future call site as well as the ones already patched by hand. Every production call site already had a real identity in scope and needed no behavioural change; a refused identity mismatch now also logs a `tracing::warn!` so the refusal is observable rather than silent.
