- **Shutdown's non-reaping exit peek: bounded EINTR retry, an honest error-classification comment, quieter logging, and a test-only shell-injection hazard closed**

  `observe_exit_without_reaping`'s non-reaping `waitid` peek (graceful shutdown's phase 2) retried an `EINTR` in an unbounded loop with no reference to the grace-window deadline. Genuinely unreachable in production — `waitid(2)` documents `EINTR` only when `WNOHANG` is unset, and this call always sets it — but an unbounded retry around a syscall is worth bounding regardless. The retry now stops once the shared grace-window deadline passes (and, independently, after a small fixed number of immediate retries, so a persistent `EINTR` cannot busy-spin one agent's peek for the rest of the grace window and starve its siblings' polling), falling back to the same conservative "still running" default the surrounding code already uses for an unclassified error. The comment justifying that default previously described protecting the grace window from a *transient* failure; after the bounded retry, the only error reachable there is a permanent misuse, not a transient one, so the comment was rewritten to say that plainly rather than describe behavior the code no longer has. Because that permanent case is latent (only reachable via the misclassification the comment now documents honestly) but re-polls for the rest of the grace window when it does occur, its `warn!` now logs once per agent per shutdown instead of once per ~50ms poll — roughly 60 lines down to 1 in the scenario that triggers it. The `ECHILD` case (something else already reaped this pid — the recycled-pid hazard fork #163 is about) keeps an unconditional `warn!`, fired at most once per agent by construction since that classification stops the agent from being re-polled; this is the one runtime signal that the sole-reaper precondition was ever violated, so it is logged rather than folded silently into "exited". Separately, a test-only stand-in used by the shutdown test suite interpolated a `tempfile`-derived readiness-marker path into a double-quoted `sh -c` string; since that path is rooted under `TMPDIR`, a `$` or backtick in `TMPDIR` would have been re-parsed by the shell instead of taken literally (the mirror image of a single-quote hazard fixed the same way in PR #206). The path now travels through an env var instead, which a shell parameter expansion never re-parses. One further comment, unrelated to behavior, was corrected: a claim that skipping the pre-#163 `.all()` short-circuit "affects how promptly the early break can trigger" — it does not; only the number of `waitid` syscalls issued per round changed.

No-Test: the EINTR bound and error classification are covered by new plain `#[test]`s (`resolve_peek_outcome_tests::*`) against an extracted, injectable `resolve_peek_outcome` helper in `src/agent_pty.rs`'s `mod tests`, and the shell-interpolation fix by `command_ignores_sigterm_delivers_marker_via_env_not_script_interpolation` in the same module — none `#[spec]`-annotated, since these are internal shutdown-path hardening with no independent user-visible scenario. The warn-once suppression and the two comment corrections have no independently testable behavior beyond what those tests already pin.
