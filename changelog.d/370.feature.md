## Shell Activity Now Registers as Working

A pane's status used to come entirely from agent-emitted hooks: if a role's agent shelled out to run something long — `cargo build`, a release script — with no hook event firing in between, the pane sat on a stale "Idle" while a command was visibly still running.

The daemon now also watches each pane's PTY foreground process group directly. When it differs from the pane's own shell — meaning a foreground command is actively running — the pane reports Working even with zero agent-emitted events in that window, and reverts to Idle once the command finishes. This never overrides a real status like Thinking, WaitingForInput, or Error; it only fills the gap where nothing more specific is already known.
