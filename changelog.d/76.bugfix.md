Fixed two ways a worker's `work-done` report could silently disappear (upstream #331, fork #76). The daemon wrote every role's report to a fixed `.dot-agent-deck/work-done-<role>.md` path derived from role name and cwd alone, with no existence check before overwriting it. Two live orchestrations sharing a role name and directory raced onto the same file, and a worker that independently wrote its own detailed report to that same predictable path — following earlier guidance to save a durable report file — had it silently clobbered by its own next `work-done` call.

The output filename is now additionally keyed on the reporting pane, so two panes never collide on the same path. If a report already exists at the target path regardless, it is archived aside instead of being overwritten, and the orchestrator's feedback names the archived file so the collision is visible rather than silent. Separately, `dot-agent-deck work-done --task-file <path>` now refuses client-side, before contacting the daemon, when `<path>` resolves into the daemon's own `.dot-agent-deck/work-done-*.md` output namespace.
