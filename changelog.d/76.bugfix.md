Fixed two ways a worker's `work-done` report could silently disappear (upstream #331, fork #76). The daemon wrote every role's report to a fixed `.dot-agent-deck/work-done-<role>.md` path derived from role name and cwd alone, with no existence check before overwriting it. Two live orchestrations sharing a role name and directory raced onto the same file, and a worker that independently wrote its own detailed report to that same predictable path — following earlier guidance to save a durable report file — had it silently clobbered by its own next `work-done` call.

The output filename is now additionally keyed on the reporting pane, so two panes never collide on the same path. If a report already exists at the target path regardless, it is archived aside — to a freshly-allocated, never-reused slot, not a single fixed name, so a *third* collision on the same path can no longer silently destroy the *first* archived report by replacing the second one — and the orchestrator's feedback names the archived file so the collision is visible rather than silent. In the rare case the archive step itself fails, the incoming report is not written at all: the existing file is left untouched rather than overwritten, and the failure is called out explicitly in the orchestrator's feedback. Separately, `dot-agent-deck work-done --task-file <path>` now refuses client-side, before contacting the daemon, when `<path>` resolves into the daemon's own `.dot-agent-deck/work-done-*.md` output namespace — including when that resolution only becomes apparent after following a symlink, whether `<path>` is itself a symlink into the namespace or reaches it through a symlinked intermediate directory.
