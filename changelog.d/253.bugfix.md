## The deck's `delegate` / `work-done` instructions now name the running binary, not a baked-in literal

Every prompt worker-agent-deck generates for orchestrators and workers hardcoded the literal `dot-agent-deck` into its `delegate` and `work-done` CLI examples, even though these instructions are executed by name through `$PATH`. A build installed under a different file name told its agents to run a command that was not itself — silently, since both calls write to the unversioned hook socket and are fire-and-forget: no error surfaces anywhere, the signal just never arrives.

The generated `delegate` and `work-done` command examples now name the file name the running binary actually resolves to, falling back to the crate's default literal only when that name is unusable — not on `$PATH`, or unsafe to interpolate unquoted into a generated shell command.

Separately, this fork's own `.dot-agent-deck.toml` hardcoded the old literal in two of its worker role instructions. Those now name `worker-agent-deck`, this fork's installed binary — a fork-local fix, since that file is config text the deck reads to build worker prompts, not code the fix above can reach.
