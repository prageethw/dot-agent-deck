- **A Codex pane whose native hook install/trust fails no longer has its remit permanently abandoned**
  `ConfirmationCapability` for a Codex-identity pane was resolved from agent type alone (`Codex` always reports), so a pane whose native hook genuinely failed to install/trust — a real, anticipated, non-crashing failure that degrades events to stdout classification — was still misclassified `Reports`. It burned the full 60s escalating-backoff retry cycle against a live interactive Codex TUI, then permanently abandoned the tab's remit at the deadline, even though `Emitter::emit_with_metadata` hardcodes `user_prompt: None` on that degraded path, making TEXT confirmation structurally impossible for that pane. `dot-agent-deck wrap`'s Codex hook install/trust outcome (`codex_spawn_prep`) is now surfaced on the wrapper-fork `SessionStart` and recorded per-pane (`AppState::codex_hook_trust_failed`); `delivery_capability` now resolves `Reports` only once the hook is known-successful for that specific pane, resolving to `CannotReport` otherwise so the pane finalizes honestly (trusting the single write) instead of retrying and then abandoning. A Codex pane whose hook installs/trusts successfully is unaffected. Issue #254 is now closed.
