## Orchestrator seed prompts to Codex no longer confirm delivery on the strength of a redrawn screen

worker-agent-deck delivers each role's opening prompt to its agent pane and then waits for a signal that the agent actually received it before moving on. For Codex, that signal used to accept any sign the pane had produced new output — including output that had nothing to do with the prompt at all, such as boot chatter from the terminal redrawing itself. A prompt that was silently lost in transit could still look delivered, because the pane printing *anything* was enough.

That signal is gone. Delivery to Codex now confirms only when the agent's own transcript shows it actually received the specific prompt that was sent — the same mechanism already used elsewhere, now reliably reached for Codex as well. A prompt that truly never arrived is reported as unconfirmed and retried, instead of being marked delivered on the basis of unrelated screen activity.

Nothing changes for a healthy delivery: a prompt that lands is still confirmed quickly. The difference only shows up on a genuinely lost write, which is now correctly retried instead of silently accepted as done.
