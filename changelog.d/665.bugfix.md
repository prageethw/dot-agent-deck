Fixes `worker-agent-deck`'s `Prmt:` line rendering a Unicode bidi override (e.g. `U+202E` RIGHT-TO-LEFT OVERRIDE) sent through a `UserPromptSubmit` event's prompt text. Following the same pattern PR #662 applied to `display_name`/`tool_name`/`tool_detail` for issue #562, `event.user_prompt` is now sanitized at the `apply_event` ingest choke point before it is stored on `session.last_user_prompt`/`session.first_prompts`, and the daemon-echo hydration scrub (`sanitize_record_tab_membership`) now routes `live.last_user_prompt` and every `live.first_prompts` entry through the same control-and-bidi scrub used elsewhere instead of a `Cc`-only strip that let a bidi-only string with no ASCII control bytes through unstripped. The same upgrade also applies to `active_tool.name`/`.detail` on that hydration path, closing the residual gap where an older daemon's `Cc`-only echo could still reach `daemon status`'s `TOOL` (and, via the #664 half of this same fix, `CWD`) columns.
