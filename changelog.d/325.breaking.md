## An older daemon paired with this build now refuses EVERY typed-slug orchestration spawn, not just a colliding one

**Behavioural change, no wire-shape change.** The Nth-concurrent-orchestration gate (`root_checkout_has_live_sibling`, see `changelog.d/325.2.bugfix.md`) fails closed when it cannot get an authoritative answer from the daemon — this already shipped as a bugfix for the case where the daemon is unreachable entirely. It also fails closed on a *reachable but too-old* daemon: one that answers with the legacy `agents` field and no `agent_records` at all. That daemon is too old to report orchestration tab membership, so the gate cannot tell "no live sibling" from "can't tell" and refuses rather than guessing.

The gate runs before either the shared-checkout or the isolated-clone provisioning arm, and it runs for every orchestration spawn that carries a worktree slug — not only the second-or-later one against a given checkout. So a current TUI paired with an older daemon (pre-dating this gate) now refuses to open **any** orchestration with a typed worktree slug, including the very first one against a checkout, because the gate cannot distinguish "daemon too old to answer" from "daemon down" — both fail closed identically.

No `PROTOCOL_VERSION` bump is included: the wire shape itself did not change (an older daemon's `AttachResponse` was always missing `agent_records`; nothing new is being sent or expected). This is a semantic break behind a stable wire, per CLAUDE.md rule 12 — the same wire shape now means something the old daemon cannot satisfy.

**Recovery:** restart or upgrade the daemon to a build that populates `agent_records` on `ListAgents` (any build carrying issue #325's M3 gate). A refusal names this in the status message rather than failing silently.
