Fixes two independent owner-identity collision edges (fork issue #222). First, `validate_task` (`src/config.rs`) never bounded a `ScheduledTask.name`'s length: an overlong name — long enough that its `issue-dispatch:{name}#{issue}` marker-creator string exceeds `sanitize_marker_creator`'s 200-character truncation cap (`MARKER_CREATOR_MAX_CHARS`, `src/worktree_reclaim.rs`) — let two distinct scheduled tasks collide onto the same truncated creator string, so a worktree marker written by one could be misattributed to the other. `validate_task` now rejects, at load time, any `task.name` longer than `DISPLAY_NAME_MAX_LEN` (the same cap the daemon already enforces on a live orchestration's display name), reported as a `ScheduleLoadError` like the existing missing-`command` check rather than letting the entry load and collide later. Second, the New Pane form's `NewPaneFormState::name_collision` (`src/ui.rs`) only checked a typed name against live orchestrations' names, so typing the literal `unknown` was accepted even though `orchestration_creator_string` resolves it to `orchestration:unknown` — byte-identical to `ORCHESTRATION_UNKNOWN_SENTINEL`, the reserved value every nameless spawn's marker-creator string already collapses to. `name_collision` now also returns `true` when the typed name resolves to that sentinel, blocking submission and rendering the existing name-collision warning the same way an ordinary live-name collision does.
