## Worker (Mode) tabs now carry their status color too

Clicking into a worker tab used to highlight it with a plain underline, no matter what its agent pane was doing — an errored or waiting-for-input worker looked exactly like an idle one in the tab strip, so you had to switch into each tab to find out which one actually needed you. Only orchestration tabs got the color treatment.

Worker tabs now color their label the same way orchestration tabs already do: by the status of their own agent pane, in the same Error (red) > Needs Input (yellow) > Working (green) > Thinking (blue) priority order, with idle tabs colored in the idle color too — every state now carries a color, with no exceptions. A worker tab whose agent hasn't spawned yet renders in the idle color for the same reason. This does mean an idle tab's label is lower-contrast than before on a dark terminal, a trade-off accepted so a tab's color always matches its worker's status color exactly.

The Dashboard tab is deliberately left out of this — coloring it by every session on the deck at once would leave it tinted almost all the time, which defeats the point of the signal. This completes `worker-agent-deck`'s tab-status-color feature to cover every worker, not just orchestrations, which is what the originating upstream request actually asked for.
