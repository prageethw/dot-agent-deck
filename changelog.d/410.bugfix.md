## `display_name` metadata is now sanitized and length-clamped on ingest

`AppState::apply_event` already sanitized and length-clamped `event.model` on ingest (PRD fork#378), but `display_name` metadata (`DISPLAY_NAME_METADATA_KEY`) arriving on the same hook-socket wire was stored with only an `is_empty()` filter — a hostile or unbounded `display_name` (Unicode bidi/format-character overrides, an arbitrarily long value) reached `SessionState.display_name`, and from there the dashboard render path, unsanitized — issue #410. `display_name` is now routed through `terminal_sanitize::sanitize_for_terminal_display` and then clamped to `DISPLAY_NAME_MAX_LEN` (bound to `agent_pty::DISPLAY_NAME_MAX_LEN`, the same 128-byte cap the rename path's `is_valid_display_name` already enforces, so ingest and rename agree on one rule instead of two) before the emptiness check and storage.
