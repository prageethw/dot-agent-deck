Fixed `dot-agent-deck delegate` reporting success for a delegation that armed nothing. The daemon resolves each requested role to a worker pane before dispatching — dropping unknown role names and refusing to target the orchestrator's own role — but the CLI's confirmation used to echo the raw request instead of what actually resolved, so an unknown or self-targeted role still printed `Delegated to <role>.` even though no worker was ever notified.

`delegate` now fails (non-zero exit, `Error: delegate rejected — …`) when none of the requested roles resolved to a pane. When some roles resolve and others don't, the call still succeeds — a real worker did get armed, and failing the whole call would risk an orchestrator retrying and delegating that same worker twice — but the CLI now prints a separate warning naming the role(s) that were requested and not delegated, so the two cases no longer look identical on the terminal.

Also fixed a related case of genuine message loss: a Pi start role's very first delegate could vanish entirely. Roles used to spawn in configuration order, and a start role's seed prompt became pullable as soon as its own child pane finished spawning — so the orchestrator could act on that seed and issue a delegate before the target worker's own pane had finished being created, and the delegate silently resolved to nothing. Non-start roles now spawn first, and registration completes before any start role's seed becomes pullable, so a start role's first delegate always has a real pane to land on.
