Fixed a case of genuine message loss: a Pi start role's very first delegate could vanish entirely. Roles used to spawn in configuration order, and a start role's seed prompt became pullable as soon as its own child pane finished spawning — so the orchestrator could act on that seed and issue a delegate before the target worker's own pane had finished being created, and the delegate silently resolved to nothing. Non-start roles now spawn first, and registration completes before any start role's seed becomes pullable, so a start role's first delegate always has a real pane to land on.
