## A delivery to a pane named with no target identity, or no session generation on a pane that already has a conversation, is now refused instead of possibly being misdelivered

A write-and-submit to a paned target that named no expected agent id, or no expected session generation on an attached pane that already has a conversation, could previously be delivered anyway — keyed by pane id alone, with no confirmation of who or which session actually received it. Both axes now fail closed: a caller that supplies no target identity is refused before any write is attempted, and an attached pane with a recorded hook session (or at least one prior closed generation) but no named session generation on the write is refused at delivery time.

An attached pane with **no** hook history at all — one that has never had a conversation — is unaffected and still accepts a write with no named session generation, exactly as before this fix; this preserves the deck's own 10-second no-`SessionStart` fallback for agent types that never emit that hook. See the `.breaking.md` fragment for why the session-generation axis is classified as a breaking behavioural change rather than a plain bugfix.
