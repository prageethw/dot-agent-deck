Fixed the release skill's cleanup detection script (`.claude/skills/dot-ai-tag-release/cleanup.sh`, Step 6) offering worktrees and branches for deletion that must never be removed. The worktree loop excluded only the worktree the script happened to be running from, not the default branch — since a branch's tip is trivially an ancestor of itself, the root checkout was offered for removal whenever the script ran from any other worktree, which is precisely what this project's worktree-per-fix convention requires. This fired for real during the v0.36.0 release. Separately, `fork-only` — the branch the fork's entire upstream-sync model rests on — was excluded nowhere in any of the three detection loops, and reads as "merged" immediately after every fork/upstream sync. Both branches are now guarded by one shared long-lived-branch check applied consistently across the worktree, local-branch, and remote-branch loops.

Also fixed both of the script's `gh pr list` queries resolving against this repository's parent (`vfarcic/dot-agent-deck`) instead of the fork, because neither passed `--repo`. This meant the open-PR guard — the script's own comment called it "the guard that matters most" — protected none of the fork's own open PRs, and every `gh` failure was silently swallowed, so a degraded run was indistinguishable from a clean one. Both queries are now pinned to the fork's own repository, a second query now also checks upstream (an open upstream PR's head branch name is one of our own branch names, since the fork proposes its own branches upstream), and a failed or missing `gh` now surfaces as `PR_STATE_DEGRADED=true` in the script's output instead of failing silently.

Finally, fixed the script being unable to run on macOS at all: it used bash 4+ associative arrays, and macOS ships bash 3.2 as `/bin/bash`. It now uses plain newline-delimited lookups instead, with no loss of behavior.
