Fixed `.claude/skills/dot-ai-tag-release/cleanup.sh` (the release skill's worktree/branch cleanup detection, Step 6) offering worktrees and branches for deletion that must never be removed. The root checkout is now excluded by its own path, not by matching a branch name, so it stays excluded no matter what branch it is on — previously it was only excluded while sitting on `main`, and the routine post-merge state of running this project's worktree-per-fix convention (the root checkout on some other, merged branch) is exactly what slipped through and got offered for real during the v0.36.0 release. `fork-only`, the branch the fork's upstream-sync model depends on, is excluded everywhere too, and every remaining way the script's PR-state or ref-freshness data could silently go stale — a failed or missing `gh`, an undetermined repository slug, a truncated result page, or a failed `git fetch --prune` — now surfaces as `PR_STATE_DEGRADED=true` in the script's output instead of looking like a clean run.

Also fixed the script being unable to run on macOS at all: it used bash 4+ associative arrays, and macOS ships bash 3.2 as `/bin/bash`.
