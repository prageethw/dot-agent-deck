Closed most of a race in the shell-activity scan that could make a pane read **Working** for a moment with nothing actually running in it. The scan lists the machine's processes at one instant and then asks the kernel which POSIX session each one belongs to at a slightly later one. A process that exits in between frees its process id for immediate reuse, so the answer could describe a completely different process — and an unrelated process in another session looks exactly like the detached shell command the signal is watching for.

Each session answer is now confirmed against a second process listing taken afterwards, and is discarded unless the process id still has the same parent and the same command line. A discarded answer counts as "unknown", never as evidence that a pane is busy. The race cannot be closed entirely without an atomic snapshot the operating system does not offer: a process id recycled into a process with the same parent *and* an identical command line is still indistinguishable.
