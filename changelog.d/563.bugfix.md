Fixes the isolated-clone arm of spawn-rollback dropping a dispatched agent's registry entry even when its own cleanup attempt failed — `attempt_isolated_clone_cleanup` failing left the clone directory on disk with nothing recording that fact, since `should_drop_registry` was declared `true` and never reassigned on that arm (unlike the shared-checkout arm's `should_drop_registry = !remove_failed`, issue #473's fix, a few lines below).

The isolated-clone arm now sets `should_drop_registry = cleaned_up_by.is_some()`, mirroring the shared-checkout arm's shape: the registry entry is dropped only when cleanup actually succeeded, and retained — the only remaining record that the clone is still on disk — when it didn't.

Pinned by `spawn_rollback_retains_registry_entry_when_isolated_clone_cleanup_fails` (`src/dispatch.rs`).
