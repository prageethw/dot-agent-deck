## Session cards can show which model an agent is running, not just which tool

The agent-type badge added in fork #339 tells you a card is running Claude Code, Codex or Pi. It could not tell you *which model* — so two panes running Opus and Haiku under the same tool looked identical, which is exactly the pair you most want to tell apart when one is thinking hard and the other is meant to be cheap.

The badge now carries the model alongside the tool: `ClaudeCode (sonnet-5) · my-session`. Everything about how you reach it is unchanged, because this reuses fork #339's mechanism rather than adding a second one — it is hidden by default, `Ctrl+D` then `Ctrl+M` (or a bare `m` from command mode) toggles it, and the toggle applies immediately to every card on every tab including cards opened afterwards.

**The model is what the agent actually reports, not a label configured somewhere.** Agents already post it on their hook payloads — Claude Code sends `model` on `SessionStart`, Codex sends it on tool events — and the deck was previously discarding it. Nothing needs configuring, and a role whose `command` is an opaque wrapper like `devbox run claude-opus-devbox` still gets the right answer, because the answer comes from the running agent rather than from parsing that string. It also follows a model that changes mid-session rather than freezing at whatever started.

Raw model ids are long and repeat their vendor in every card (`claude-sonnet-5`, `gpt-5.1-codex-mini`), so a leading vendor prefix is dropped for display — `claude-sonnet-5` shows as `sonnet-5`. This is deliberately a *vendor* prefix rule and not a per-model lookup table: vendor names are stable while model ids churn constantly, so a table would have gone stale on the next release and shown the wrong name with no way to notice. A model id from a vendor the deck has never heard of passes through untouched rather than being mangled or dropped.

**What an agent reports is treated as untrusted, because it is.** The card title is the surface you use to tell an orchestrator from a worker, and any agent on the deck can post to the hook socket. So the model is length-capped on a character boundary and stripped of Unicode format characters — the bidi-override and zero-width class that can visually reorder or conceal the text around them without a single control byte. Without the cap, a long model would have pushed the session's own identity off the title entirely; with arbitrary text it could have forged one.

Two robustness notes that matter more than the feature itself. A model reported in an unexpected shape — an object, a number, a provider/model pair — now degrades that one field to "unknown" instead of failing the payload; previously a strictly-typed field would have rejected the whole hook event, silently taking that agent's status updates with it. And the model survives detaching and reattaching a TUI, which needed it added to the reconnect snapshot: because Claude Code reports the model only at session start, a badge lost on reconnect would never have come back for the life of that session.
