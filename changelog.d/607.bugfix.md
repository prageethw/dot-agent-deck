Opening an orchestration against two different subdirectories of the same project (say `team-a/proj` and `team-b/proj`) that happened to suggest the identical orchestration name could silently provision both into the same physical isolated-clone workspace — two orchestrations the user believed were independent ended up sharing one clone's branch, checkout, and ownership marker (issue #607).

The isolated-clone workspace name is now derived from the picked subdirectory's own position under the project, not just the shared project root and the orchestration name, so two such picks provision into genuinely separate clones. Opening a single orchestration directly at a project's root is unaffected — it still provisions to exactly the same location it always has.
