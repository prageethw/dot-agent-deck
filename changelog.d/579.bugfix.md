Fixes linkage-check's shared fixture-git-invocation helper (`repo_state.rs`'s `mod real_git::Sandbox::git()`) not neutralizing git's location-discovery environment variables — `GIT_DIR`, `GIT_WORK_TREE`, `GIT_COMMON_DIR`, `GIT_INDEX_FILE`, `GIT_OBJECT_DIRECTORY`, `GIT_ALTERNATE_OBJECT_DIRECTORIES`, `GIT_CEILING_DIRECTORIES`, and `GIT_NAMESPACE` — alongside the config-discovery variables (`GIT_CONFIG_GLOBAL`/`GIT_CONFIG_SYSTEM`) it already neutralized. Left ambient, these vars could steer a fixture `git` invocation past the sandboxed test repository and onto whatever repository a parent process's environment pointed at instead — reachable from a pre-commit hook, `git rebase --exec`, or `git bisect run` context that legitimately sets these vars before spawning the test binary — reading or even writing that repository's real state (demonstrated in fork issue #579 as both a read escape, where `git rev-parse HEAD` returned the ambient repo's HEAD instead of the fixture's, and a write escape, where a fixture commit moved the ambient repo's HEAD). All eight vars are now stripped from the fixture `git` invocation's environment via `env_remove`, restoring git's normal auto-discovery-from-`cwd` behaviour, which is what the sandbox intends. This module's doc comment claim that "nothing here can read or write the checkout these tests are running inside" is now accurate.

No-Test: the regression is pinned by `sandbox_git_ignores_ambient_git_dir_and_git_work_tree` in `xtask/linkage-check/src/repo_state.rs`'s `mod real_git`, a real test (RED before this fix, GREEN after — see PR #663) rather than a documentation gap; it is a plain `#[test]`, not `#[spec(...)]`, matching every other test in that module, and R3's spec-test-delta scan only walks the top-level `src/`/`tests/` trees (`list_tests.rs`'s `git_ls_tree(repo_dir, reference, "src"|"tests")`), not `xtask/linkage-check/src/`, so it cannot see this test regardless of tagging.
