Fixed an orchestration role occasionally showing as working when the agent never actually received its starting prompt. The daemon sometimes couldn't tell whether the bytes it wrote for a spawn-time role prompt had truly reached the agent's input — a CR that landed as a plain newline in the agent's own input box, for instance, looks identical to a real submit from the daemon's side. Previously "the write went through" was treated as good enough, so the pane sat there showing as working while the agent itself never saw a prompt at all.

The daemon now waits for independent confirmation that the prompt was actually submitted before calling a role delivered, and retries once if that confirmation doesn't show up in time. A stale or unrelated confirmation — an agent that happened to already be busy for some other reason before our prompt was even sent — no longer counts; only a submission that clearly happens after our write does. If the daemon still can't get independent confirmation before giving up, the retry itself is what fixes the original bug this PRD closed: earlier builds silently wrote the retried prompt to a cache and never resent it, so the retry never really happened. It now reaches the agent for real. And if a prompt genuinely landed but confirmation never arrived in the time allotted, the daemon now reports it as delivered-but-unconfirmed with a warning, rather than incorrectly claiming it was never delivered at all.
