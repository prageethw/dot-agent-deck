## `issue release` — cleanly unlock a stale issue claim

`worker-agent-deck issue claim` could claim an issue and transfer a claim, but had no way to release one. A stale claim — one left behind by an orchestration that stopped — locked the issue against re-entry until someone cleared it by hand: a comment plus a label removal, with no check on who was doing it or whether there was actually a claim to clear.

**`worker-agent-deck issue release <n> --repo <owner/name>` now does this properly.** It refuses on an issue that isn't actually claimed (catching a typo'd number instead of silently succeeding), and it refuses when a different identity holds the claim unless you explicitly override it.

**Releasing someone else's claim requires the same two-flag friction `issue claim --takeover` already has.** `--force` alone is not enough — you also need `--confirm-stopped`, deliberately, so an agent can't satisfy the override in the same breath it discovers the conflict. This applies whether the prior holder is known or the claim state is ambiguous (labelled, but no comment ever named who held it).

**Every release posts a comment recording who released it, and — for a forced release — who it was released from.** An optional `--reason` lets you record *why* (merged, abandoned, superseded), rendered safely so it can never post a live mention or an unintended cross-reference.
