## `unconfirmed_retry_delay`'s first-retry floor gained a test-only override seam

PR #525 (fix for issue #422 item 2) raised `unconfirmed_retry_delay`'s first-retry floor from 500ms to 10s and its cap to 15s, correctly closing a race against a genuine late TEXT confirmation — but left the function with no test-only override seam, so the daemon-side unit test `dispatch_016_detached_retry_stops_before_replacement_or_clear` was left burning three real ~10s-scale wall-clock waits per run, making it the fast tier's single slowest test.

`unconfirmed_retry_delay` now reads its first-retry floor through a new `unconfirmed_retry_base()` accessor, mirroring `crate::ui::send_retry_base`'s existing `#[cfg(any(test, debug_assertions))]` pattern exactly: overridable via `DOT_AGENT_DECK_TEST_UNCONFIRMED_RETRY_BASE_MS` in test/debug builds (clamped to the 15s cap, with a one-time warning on an out-of-range or unparseable value), fixed at the production 10s in release builds. Production behavior is unchanged when the env var is unset — `unconfirmed_backoff_escalates_then_caps` still pins the real 10s/15s schedule with no override in effect. `dispatch_016`'s three real-wait sub-cases now set the override to 300ms for the whole test, and their deadlines/sleeps are shrunk to match, cutting roughly 30 seconds of real wall-clock time off the test without changing what it proves.

Pinned by the new `unconfirmed_retry_base_honors_test_override` unit test in `src/prompt_delivery.rs` (unset leaves the default, a valid override is honored, a non-numeric value falls back, an out-of-range value clamps to the cap) and by `dispatch_016` itself now completing in milliseconds instead of tens of seconds.
