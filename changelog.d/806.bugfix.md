## An orchestration role pane no longer gets two cards when a hook event arrives before its placeholder

If a hook event for a freshly spawned pane reached the deck before the deck had inserted that pane's placeholder card, the event created a session of its own and the placeholder was then added beside it, so one pane showed two cards. This was seen on orchestration role panes, where `wrap`'s immediate boot `SessionStart` or the agent's own can win that race. The spawn-time placeholder step now adopts the session already on the pane instead of adding a second one, and the card ends up in the same state whichever of the two arrived first: an agent that has already reported keeps its status, and a pane that has only seen `wrap`'s boot event still reads `Starting…`.
