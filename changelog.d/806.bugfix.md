## An orchestration role pane no longer gets two cards when a hook event arrives before its placeholder

If a hook event for a freshly spawned pane reached the deck before the deck had inserted that pane's placeholder card, the event created a session of its own and the placeholder was then added beside it, so one pane showed two cards. This was seen on orchestration role panes, where `wrap`'s immediate boot `SessionStart` or the agent's own can win that race. The spawn-time placeholder step now looks at what is already on the pane, and the pane ends up with the one card it would have had if the placeholder had been inserted first: an agent that has already reported keeps its status, a pane that has only seen `wrap`'s boot event still reads `Starting…`, and a session reported under a different agent id keeps the pane to itself instead of gaining a placeholder next to it. An adopted card takes its start time the way a placeholder does (the pane's remembered start, or the deck's own clock), and its last-activity time is the later of the deck's clock and the early event's own timestamp, so a stale early timestamp does not backdate the card.
