## Release workflow: the desktop build job no longer floats the pnpm version, keeps no stored credential and has a time limit

The release workflow's desktop bundle job installed pnpm with `version: 12`, which floats to whatever 12.x is latest, checked the repository out with the default of leaving the job's write-scoped token in the git config where pnpm and every dependency install script could read it, and had no time limit beyond GitHub's six-hour default. The pnpm version is now pinned exactly (the same version as the CI jobs), the checkout no longer persists the credential, and the job has a time limit, so a bad pnpm release, a compromised dependency or a hang can no longer reach or stall the build of the bundles users install.
