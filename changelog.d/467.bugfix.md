## The default log file moved off a predictable /tmp path

When `DOT_AGENT_DECK_LOG` was left empty or set to `1`, the deck wrote its default debug log to the fixed path `/tmp/dot-agent-deck.log` — a predictable filename in a world-writable directory, opened with no protection against a symlink pre-planted there before first use (CWE-59/377).

The default now resolves under the per-user state directory instead (`~/.local/state/dot-agent-deck/deck.log` on Linux, `%LOCALAPPDATA%\dot-agent-deck\deck.log` on Windows), created owner-only (mode `0700`) the same way the daemon's own `daemon.log` already is. On Unix the file itself is now opened with the same refusal `daemon.log` already had: mode `0600`, and if the path is already a symlink, the deck refuses to follow it and logs a stderr warning instead of writing through it (logging is then effectively disabled for that run rather than silently redirected). If you previously pointed something at that path via a symlink, remove it — an explicit `DOT_AGENT_DECK_LOG=<path>` still writes exactly where you point it, unhardened, unchanged.
