## A Codex hook-trust failure found while draining pre-write events now reaches the retry veto too

Issue #459 taught the dispatch/scheduler delivery path to veto retry arming for a Codex pane whose native hook install/trust is known to have failed — but only when that failure was learned from the readiness wait that runs before the pre-write event drain. If that wait timed out before the wrapper's fork-time `SessionStart` event landed, the drain could see the failure directly and had no way to report it back: a later, metadata-free Codex event drained in the same pass would still arm the delivery, silently defeating the veto for the whole delivery.

The drain now carries that signal back to the caller and it is folded into the same veto at every point capability is decided — before the first write, during the post-write confirmation window itself (`wait_for_prompt_submission`'s own `PromptWatch::Elapsed`), during the gap drain inside the post-write confirmation loop, and into the confirmation task's own standing flag — the same accumulate-only pattern the rest of the #459 fix already uses. A hook-trust failure observed at any point during a delivery now vetoes arming for that delivery, regardless of which check happens to see it first.

This veto is TUI-observable: when it holds, `abandon_spawn_prompt` never publishes its client-visible `DeliveryNotice`, and up to ~60s of probe carriage-returns are withheld from being retyped into a live Codex pane instead of landing in it. That surface is real; it is simply pinned at the unit level here rather than through a full `#[spec]` TUI scenario, because every branch this fix touches is internal capability-resolution bookkeeping (which event convinces a delivery loop that a producer can or cannot ever report back) that a unit test pins more directly and deterministically than a TUI-driven scenario could — and #459's own fragment was not pinned this way for the same reason; it satisfied R3 by touching an existing `#[spec]` test's body rather than carrying a `No-Test:` line of its own.

No-Test: pinned entirely by plain `#[test]`/`#[tokio::test]` functions in `src/spawn.rs` and `src/state.rs`'s `mod tests` (including `drain_pre_write_events_reports_hook_trust_failure_even_when_a_later_event_arms_capability` and `wait_for_prompt_submission_reports_hook_trust_failure_even_when_a_later_event_arms_capability`) rather than a `#[spec]`-annotated one — see the paragraph above for why unit-level pinning fits this change better than a TUI scenario would.
