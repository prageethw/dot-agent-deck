**`worker-agent-deck worktree list` now names a specific owner for every worktree — an agent identity, a human, or a stated "unknown" — instead of a bare `owned: true/false` bit.** Previously the only signal was whether the deck could prove it created a worktree; a hand-made worktree (an ordinary `git worktree add`, the normal path when following this project's own worktree-per-change discipline) reported no owner at all, and the only way to answer "who does this belong to?" was to read `git log` authorship, which is not the same question. Every row in `worktree list --json` now carries `owner_kind: "agent" | "human" | "unknown"` beside the existing `owner` string: `"agent"` for a deck-created worktree whose ownership marker names an identity, `"human"` for an unmarked, hand-made worktree (resolved via the same `gh api user` login lookup `issue claim` already uses, rendered as `human:<login>@<host>`), and `"unknown"` when neither can be established — a pre-existing legacy marker with no recorded identity, or a login that could not be resolved (`gh` absent, unauthenticated, or failing). `worktree list` never crashes or guesses in the failure case; it says so.

**This does not change what a bare `reclaim` is allowed to remove.** Reporting an owner and deciding whether a worktree can be deleted without `--yes` are kept as two independent questions, resolved independently: a human-owned worktree is now correctly *named* as such, but removal authority still comes strictly from the deck's own creation marker, exactly as before. A merged, clean, human-owned worktree still requires `--yes`.

`worktree list --json --mine` also now surfaces two disagreement cases directly in the JSON document (previously stderr-only, or silently dropped) so an automated consumer reading stdout alone can see them: a row where the ownership marker names the caller but the independent ownership check disagrees, and a row that is deck-owned but carries no identifiable marker owner (most often a pre-existing legacy marker). Neither changes which rows `--mine` returns — both are reporting-only, added to a new `warnings` array alongside the existing worktree list.

Prose in this fork calls the product `worker-agent-deck`; the binary name in a command you would actually paste and run is still `dot-agent-deck`.
