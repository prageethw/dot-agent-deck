A non-force `pane restart` could previously kill a healthy replacement worker that a concurrent `clear = true` delegation had just installed into the same pane — a TOCTOU window where the restart's crash check ran before the dispatch lock was acquired, so a delegate that installed a fresh, healthy occupant into the pane while the restart was queued behind that lock got silently killed anyway, with the restart still reporting success. The crash state is now re-checked under the dispatch lock immediately before the respawn, and refused with the same "has not crashed" error the original check gives if the pane is no longer crashed by the time the lock is held. `--force` is unaffected — it continues to bypass both checks.
