**New: `dot-agent-deck issue claim <n> [--repo owner/name] [--takeover] [--confirm-stopped]` — claims a GitHub issue and exits non-zero when someone else already holds it.** Call this a **claim**, not a lock: it is cooperative coordination against accidental collision between agents working the same deck, and replay and forgery of the claim record are explicit non-goals. The command uses three surfaces for three different jobs. The `in-progress` label says *that* the issue is held, cheap for `dispatch_decision` and any external tool to read. The **assignee** says *who owns it now* — replaced on each claim, so it always names the current holder and nobody else. The comment log says *who has held it, in order* — appended, never edited, so the history survives a takeover. `--takeover` alone still refuses, and tells you to re-run with `--confirm-stopped`; that two-step is deliberate friction, so an agent cannot satisfy its own override in the same breath it discovers the conflict. A takeover rewrites the claim record naming who it took over from — it does **not** stop the agent it took over from, which may still be running.

Two things worth stating plainly rather than discovering later. First, **the worktree's absolute path — and now also the machine's hostname — is published in a public GitHub comment on every claim.** That is deliberate — CLAUDE.md rule 23 already did this by hand, precisely so a human can cross-check a claim against `git worktree list` — but on the unattended `issue_dispatch` path, this now happens **automatically, per claim, at cron rate**, publishing the daemon host's directory layout, plus its hostname, to a public issue comment without a human in the loop for any individual claim; the two together are correlatable across every issue the same host has ever claimed, which the path alone was not. Second, **every pre-existing claim comment now reads as "no identity"**: the parser this command reads back is scoped to its own comment shape, so an issue claimed under an older format refuses with "identity unknown" the next time anyone tries to claim it. Recover with `--takeover --confirm-stopped` once you've confirmed nothing is still working the issue under the old claim.

Prose in this fork calls the product `worker-agent-deck`; the binary name in a command you would actually paste and run is still `dot-agent-deck`.
