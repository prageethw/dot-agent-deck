## A blank Worktree slug no longer skips the Nth-concurrent-orchestration clone gate

Submitting a new orchestration with the Worktree field left blank — the default most orchestrations use — could silently root a second orchestration in a root checkout a live sibling orchestration already occupies. The gate added to isolate an Nth concurrent orchestration into its own clone only ran when a Worktree slug was typed; the blank-slug path fell straight through to the shared checkout with no consultation at all.

There is no typed slug to isolate a blank submission into a clone with, so unlike the typed-slug path — which isolates into its own clone and still succeeds — a blank-slug orchestration submitted against a root checkout that a live orchestration's own directory already exactly matches now fails closed by refusing: no orchestration tab opens, no role pane spawns, and a status message tells you to type a Worktree slug to isolate the new orchestration instead. A live orchestration running in a worktree carved off that root checkout does not trigger this refusal — that is this project's own everyday workflow, and it is unaffected.
