## A blank Worktree slug no longer skips the Nth-concurrent-orchestration clone gate

Submitting a new orchestration with the Worktree field left blank — the default most orchestrations use — could silently root a second orchestration in a root checkout a live sibling orchestration already occupies. The gate added to isolate an Nth concurrent orchestration into its own clone only ran when a Worktree slug was typed; the blank-slug path fell straight through to the shared checkout with no consultation at all.

Submitting a blank-slug orchestration against a root checkout with a live sibling now fails closed the same way the typed-slug path already does: the spawn is refused, no orchestration tab opens, no role pane spawns, and a status message tells you to type a Worktree slug to isolate the new orchestration instead.
