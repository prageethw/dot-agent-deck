## A sync-dropped test no longer disappears silently, and the discipline that stops it recurring is written down

Fork issue #344: a fork test commit bundled together with the implementation it protects can be dropped along with that implementation when a later upstream sync decides the implementation is superseded — and the drop is silent, because CI just runs against a smaller `#[spec]` test population and stays green. This is what actually happened to PRD fork#197's tests in the 2026-08-15 sync, and it went on to cause two real regressions (issue #194 / PR #341, and issue #423's remit re-assertion) before either was caught.

Two changes, covering items 1 and 3 of the issue's four proposed fixes (items 2 and 4 are left as process guidance for future sync work, not mechanical changes):

- `docs/develop/fork-sync-workflow.md` now states explicitly that a future fork commit bundling a test with its implementation must not let the test's coverage disappear when the implementation is later marked superseded — split the commit before marking anything superseded, or name in the stack-table entry that the test half is being carried forward separately.
- A new `cargo xtask list-tests --compare <ref-a> <ref-b>` mode reports the `#[spec]` test population delta between two explicit refs — added, removed, modified — and exits non-zero when a test present at `ref-a` is missing at `ref-b`. It reuses the existing `compute_created`/`compute_modified`/`collect_tests_at_ref` machinery rather than reimplementing test collection. This is a manual step wired into the sync procedure's own write-up, deliberately **not** wired into the automatic per-PR `linkage-check` suite — a merge-base-vs-`origin/main` comparison is structurally vacuous on a real `pull_request` CI event and false-positive-prone on a branch mid-rebase, the same failure classes issues #259/#281 hit trying to automate something similar.

No-Test: pinned by plain `#[test]`s in `xtask/linkage-check/src/list_tests.rs`'s new `mod real_git` (real-git fixtures under `tempfile::tempdir()`, per CLAUDE.md rule 5's `mod real_git` exception) — xtask unit tests, not e2e `#[spec]`-tagged catalog scenarios, so there is no `#[spec]` delta for this gate to see.
