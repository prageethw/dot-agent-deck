## `work-done`'s Registration-Context Reader Gains Fast-Tier Test Coverage

The `work-done` CLI handler's registration-generation/daemon-boot-id reader — the fail-closed guard fork issue #358 added so a report is refused at delivery rather than silently accepted when it doesn't match the pane's current registration — is now a small, pure `read_registration_context` function instead of inline logic, with unit tests pinning its parse-and-fallback behavior (present, missing, and unparseable-generation cases) in the fast tier. Previously this logic was exercised only by credential-gated real-agent e2e fixtures that self-skip in this fork's CI, so a refactor here could have silently broken it with every check staying green. This is a pure extraction — no behavior change for real callers.
