## Dispatch and scheduler deliveries no longer retry a Codex pane whose hook install is known to have failed

worker-agent-deck decides whether an agent pane can ever confirm a delivered prompt by checking what kind of agent it is. For Codex, that check used to say "yes" unconditionally — even for a pane whose native hook install/trust had already been reported as failed, which can never emit the text confirmation a delivery is waiting for. The TUI-attached delegate path was fixed for this case previously; the dispatch/scheduler path (used by `dispatch`, scheduled cards, and orchestration delegation) had the same gap.

That gap is closed. The dispatch/scheduler path now reads each Codex pane's own reported hook-trust outcome, at every point capability is decided — before the first write, during the post-write confirmation watch, and across the pane's boot sequence — and a known hook-trust failure now vetoes arming retries for that delivery, even if some other signal would otherwise have latched it. A pane whose hook never installed correctly is left provisional instead of burning through the full retry window against a live interactive Codex session and then abandoning the task at the deadline.

Nothing changes for a Codex pane whose hook installs and trusts normally — delivery confirmation there is unaffected.
