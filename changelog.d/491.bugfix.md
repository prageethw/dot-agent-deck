## `ensure_owner_only_dir` no longer follows a symlink planted at the target path

`ensure_owner_only_dir` (`src/platform/fsperm/unix.rs`) created and `chmod`'d the directory at the caller-supplied path without first checking whether that path was itself a symlink. A same-uid attacker who pre-planted a symlink at the target path could get their own directory silently tightened to `0o700` and treated as owner-only, regardless of what real permissions it started with — the caller believed it had secured its own directory when it had instead validated an attacker-controlled one.

The function now stats the target path with `symlink_metadata` (lstat semantics, which does not follow the final path component) before creating or chmod'ing anything, and refuses with an `io::Error` if a symlink is found there. The ordinary first-time-creation case, where nothing exists at the path yet, is unaffected.
