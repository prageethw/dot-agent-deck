**New: `dot-agent-deck worktree list` shows an OWNER column, and `worktree list --mine` lists only the worktrees the calling orchestration created.** The human table now names which orchestration created each worktree (a dash for one predating this feature, or one worker-agent-deck did not create); `--json` already carried the field. Every orchestration pane now carries a `DOT_AGENT_DECK_WORKTREE_OWNER` environment variable — the exact identity stamped into its own worktrees' `created-by:` markers — mirroring the existing `DOT_AGENT_DECK_PANE_ID`, so `worktree list --mine` can match "mine" by comparing two plain strings, with no daemon round-trip and no dependency on in-memory state (it still works immediately after a daemon restart). The identity is persisted in the saved session, so a tab that is closed and reopened restores with the SAME identity, and `--mine` still matches its earlier worktrees. A tab whose session snapshot predates this fix — saved before the identity was captured, or before this field existed at all — restores with no identity, since restore refuses to guess one; `--mine` then fails loudly for that tab alone rather than silently listing everything or nothing. Run outside an orchestration pane, or with the identity set to the `orchestration:unknown` sentinel a nameless orchestration falls back to, `--mine` fails loudly (non-zero exit, names what is missing) rather than silently listing everything or nothing — a wrong answer here would hand one orchestration another's worktrees, the fork #74 collision this feature exists to prevent.
