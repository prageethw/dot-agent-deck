**New: `dot-agent-deck worktree list` shows an OWNER column, and `worktree list --mine` lists only the worktrees the calling orchestration created.** The human table now names which orchestration created each worktree (a dash for one predating this feature, or one worker-agent-deck did not create); `--json` already carried the field. Every **freshly-created** orchestration pane now carries a `DOT_AGENT_DECK_WORKTREE_OWNER` environment variable — the exact identity stamped into its own worktrees' `created-by:` markers — mirroring the existing `DOT_AGENT_DECK_PANE_ID`, so `worktree list --mine` can match "mine" by comparing two plain strings, with no daemon round-trip and no dependency on in-memory state (it still works immediately after a daemon restart). A pane restored from a saved session does **not** carry the variable — restore does not know whether the orchestration ever created a worktree, so it deliberately assigns no identity rather than guessing one. Run outside a fresh orchestration pane, or with the identity set to the `orchestration:unknown` sentinel a nameless orchestration falls back to, `--mine` fails loudly (non-zero exit, names what is missing) rather than silently listing everything or nothing — a wrong answer here would hand one orchestration another's worktrees, the fork #74 collision this feature exists to prevent.
