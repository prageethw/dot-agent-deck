- **The features-config ancestor search no longer trusts a world-writable directory (Unix only)**

  On Unix, the `[features]` flag resolver walks up from the working directory looking for the project's `.dot-agent-deck.toml` (fork issue #303). That walk was unbounded, so a deck launched anywhere under a shared, world-writable directory (like `/tmp`) could adopt a config another user planted there — including when the launch directory itself was the world-writable one. A world-writable ancestor is now declined — with a warning naming the declined path, surfaced on stderr at startup as well as to the log — and the search continues upward to the nearest safe ancestor, so discovery from a normal project subdirectory keeps working exactly as before. If no ancestor can be trusted at all, the deck no longer guesses: experimental features stay off and no config file is watched for the rest of the run, rather than silently falling back to a path it just declined. Windows is unchanged; the ancestor walk there is still unbounded and is tracked separately as fork issue #383.

No-Test: the resolver logic itself (a guarded fallback, a three-state directory-safety check, a "nowhere trustworthy" outcome) is pure data and is covered by the plain `#[test]` fixtures in `src/config.rs`'s `mod tests`, extended in this round. Its one user-visible surface — the startup stderr warnings this now prints — is already covered by the `startup_warning_001`–`003` end-to-end tests in `tests/e2e_features_status.rs`; a dedicated case for the newly-declined-ancestor path is tracked as a follow-up rather than added here.
