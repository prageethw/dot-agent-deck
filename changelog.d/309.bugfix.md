- **The features-config ancestor search no longer trusts a world-writable directory**

  The `[features]` flag resolver walks up from the working directory looking for the project's `.dot-agent-deck.toml` (fork issue #303). That walk was unbounded, so a deck launched anywhere under a shared, world-writable directory (like `/tmp`) could adopt a config another user planted there. A world-writable ancestor is now skipped — with a warning naming the path and the reason — and the search continues upward, so discovery from a normal project subdirectory keeps working exactly as before.
