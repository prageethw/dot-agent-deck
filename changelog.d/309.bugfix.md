- **The features-config ancestor search no longer trusts a world-writable directory (Unix only)**

  On Unix, the `[features]` flag resolver walks up from the working directory looking for the project's `.dot-agent-deck.toml` (fork issue #303). That walk was unbounded, so a deck launched anywhere under a shared, world-writable directory (like `/tmp`) could adopt a config another user planted there — including when the launch directory itself was the world-writable one. A world-writable ancestor is now declined — with a warning naming the declined path, surfaced on stderr at startup as well as to the log — and the search continues upward to the nearest safe ancestor, so discovery from a normal project subdirectory keeps working exactly as before. Windows is unchanged; the ancestor walk there is still unbounded and is tracked separately as fork issue #383.

No-Test: pure-data unit fixes to the ancestor-walk resolver (a guarded fallback, a reordered decline predicate), with no TUI/daemon protocol surface — covered by the existing plain `#[test]` fixture in `src/config.rs`'s `mod tests`, extended in this round. A `#[spec]` integration test would exercise the same resolver through a heavier PTY harness for no additional coverage.
